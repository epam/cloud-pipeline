# [Negative] [MANUAL] Extract archive is dimmed at the archive-task limit, and explains why

Test verifies that, where the user does not have enough archive-task allowance left for the
archives they selected, the **Extract archive** item is dimmed and cannot be clicked, and an
information icon beside it gives the reason on hover - the tooltip appearing above the open menu
rather than behind it. It also verifies that the item is not offered at all where the storage or
the user's permissions rule extraction out.

**_Note_**: manual, because it needs the user sitting at the limit the
`system.async.tasks.config` preference's `maxUserTasks` sets, which has to be arranged by an
administrator for the run rather than reached through the GUI.

**Prerequisites**:
- An administrator, to set the preference below
- A user with **READ** and **WRITE** permissions on an S3 object storage (or an NFS storage whose
  share is mounted as NFS)
- The same user with **READ** permission only on another such storage
- Any Azure or GCP storage the user can write to

**Preparations**:
1. As the administrator, set `maxUserTasks` in the `system.async.tasks.config` preference to `1`
2. Login as the user from the Prerequisites
3. Open the writable storage from the Prerequisites, and upload an archive (e.g. `one.zip`) into it
   with **Upload**
4. Select a folder in that storage, choose **Download archive** from the selection button and
   confirm with **OK**, so the whole allowance is in use

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Select `one.zip` alone and click the selection button | <li> The **Extract archive** item is listed, dimmed, and clicking it does nothing <li> An information icon is shown beside its title |
| 2 | Hover that information icon | <li> A tooltip appears, naming the number of archive tasks already in progress and the limit <li> It is drawn **above** the open menu, fully readable, not behind or clipped by it |
| 3 | Move the pointer across the dimmed item and its icon | The cursor is the same "not allowed" cursor over the whole row, the icon included - it never changes to a hand over part of the row |
| 4 | Cancel the archive-download task in the **Storage tasks** window, then open the selection menu again | The **Extract archive** item is no longer dimmed, has no information icon, and queues a task when clicked |
| 5 | Open the storage the user has **READ** permission on only, select an archive in it and click the selection button | No **Extract archive** item is listed at all: extracting writes into the folder, so it needs write access |
| 6 | Open the Azure or GCP storage, upload an archive with **Upload**, select it and click the selection button | No **Extract archive** item is listed: the item is offered only on AWS S3 and on NFS storages whose share is mounted as NFS |

**After**:
- Cancel every archive task left in the **Storage tasks** window
- Delete the archives uploaded in the Preparations and in step 6
- As the administrator, put `maxUserTasks` back to its original value
