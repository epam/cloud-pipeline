# Downloads window: cancel a task, Status filter, paging

Test verifies that:
- clicking **Cancel** on an active task's row requests its cancellation
- by default the **Downloads** table hides cancelled and expired tasks; ticking them in the **Status** column's filter shows them
- the table is paged once more tasks match than fit on one page, and the page controls cover every matching task

**Prerequisites**:
- An AWS S3 object storage with several files exists

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Open library |  |
| 2 | Click on the storage in the library-tree |  |
| 3 | Select several files, click the **N items selected** button, click **Download archive**, then click **OK** without changing the name |  |
| 4 | Open the **Downloads** window via the grid-icon button's **Show downloads** item | The task queued at step 3 is shown, with a **Cancel** button on its row while it is still active |
| 5 | Click **Cancel** on that row | <li> The row's status changes to `CANCEL_REQUESTED`/`STOPPING` or, if the task had not started, straight to `CANCELLED` <li> The **Cancel** button disappears |
| 6 | Click the filter icon on the **Status** column's header | A checkbox filter appears, with every status ticked by default except **CANCELLED** and **EXPIRED** |
| 7 | Close the filter dropdown without changing anything | The table does not show the task cancelled at step 5 |
| 8 | Click the filter icon on the **Status** column's header again, tick **CANCELLED** as well, then apply the filter | The task cancelled at step 5 is now shown |
| 9 | Click the filter icon on the **Status** column's header again, untick **CANCELLED**, then apply the filter | The task cancelled at step 5 is hidden again |
| 10 | Repeat step 3, 11 times | 11 new, non-cancelled tasks are queued |
| 11 | Open the **Downloads** window | <li> Only 10 tasks are shown on the first page <li> Numbered page controls appear underneath the table |
| 12 | Click the control for the 2nd page | The remaining task is shown |
