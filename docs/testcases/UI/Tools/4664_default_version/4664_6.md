# The default version controls depend on the permissions

Test verifies that
- a user without the **WRITE** permission for a tool sees the **default** label, but cannot set or remove the default version
- a "symlinked" tool shows the default version of the original tool and has no controls to change it

**Prerequisites**:
- Admin user
- Non-admin user
- Test tool with the **latest** version and at least two other versions
- `<version>` is one of the test tool versions, which is not the **latest** one
- The non-admin user has the **READ** and **EXECUTE** permissions for the test tool, but not the **WRITE** one
- A "symlink" of the test tool in another tool group (see [10.8. Symlinks between tools](../../../../md/manual/10_Manage_Tools/10.8._Symlinks_between_tools.md))

**Preparations**:
1. Login as the admin user from the prerequisites
2. Set the `<version>` version as the default one of the test tool, as described in [4664_2](4664_2.md) (steps 1-4)
3. Logout

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Login as the non-admin user from the prerequisites | |
| 2 | Open the **Tools** page | |
| 3 | Select the test tool from the prerequisites | |
| 4 | Click the **VERSIONS** tab | <li> The `<version>` version has the **default** label <li> There are no "star" buttons |
| 5 | Logout and login as the admin user | |
| 6 | Open the "symlink" of the test tool | |
| 7 | Click the **VERSIONS** tab | <li> The `<version>` version has the **default** label <li> There are no "star" buttons |
| 8 | Click the **Run** button at the top of the tool page | |
| 9 | In an appeared pop-up window click **Launch** button | |
| 10 | At the **Runs** page, click the just-launched run | |
| 11 | Click the **Instance** item | ***Docker image*** field is shown with the test tool's docker image and the `<version>` tag |

**After**:
- Stop the run launched at step 9
- Remove the default version of the test tool, as described in [4664_3](4664_3.md) (steps 1-4)
