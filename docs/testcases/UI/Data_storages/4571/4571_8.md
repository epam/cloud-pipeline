# [Negative] An extraction task offers Cancel, and never Download

Test verifies that an **Extract archive** task in the **Storage tasks** window never offers the
**Download** button an archive-download task offers, whatever its status - an extraction writes into
the storage itself, so there is no artifact to hand over - and that it can still be cancelled the
same way a download can.

**Prerequisites**:
- A user with **READ** and **WRITE** permissions on an S3 object storage (or an NFS storage whose
  share is mounted as NFS)

**Preparations**:
1. Login as the user from the Prerequisites
2. Open the storage from the Prerequisites
3. On the local machine, have ready one archive file (e.g. `archive1.zip`)
4. Upload `archive1.zip` via **Upload** → **Upload and extract**, so that one extraction task is
   queued (see case 4571_4)
5. Select a folder in the storage, click the selection button and choose **Download archive**,
   confirm the name with **OK**, and wait for that task to reach a successful status
6. Open the presentation dropdown (the button with the grid icon at the top right of the storage
   view) and choose **Show storage tasks**

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Find the **Extract archive** row and look at its **Actions** | <li> A **Cancel** button is shown <li> No **Download** button is shown |
| 2 | Find the successful **Download archive** row and look at its **Actions** | A **Download** button is shown - so the absence in step 1 is about the task's type, not about the window |
| 3 | Click **Cancel** on the **Extract archive** row | The row's status changes to a cancelled or cancellation-requested status, the same way a cancelled download behaves |
| 4 | Wait for the row to settle, then look at its **Actions** again | <li> Still no **Download** button <li> **Cancel** is no longer offered, since the task is no longer active |
| 5 | Open the **Status** column's filter, tick every status, click **OK**, and find the cancelled **Extract archive** row | The row is listed, with **Extract archive** in its **Type** column and no **Download** button |

**After**:
- Delete `archive1.zip` from the storage
- Delete the archive the download task produced, if the deployment keeps it
