# A commit into a tool with a default version doesn't create the latest version

Test verifies that a commit into a tool, which has no **latest** version,
- doesn't create the **latest** version, if a default version is set for the tool
- gives the new version the settings of the default version of the tool
- creates the **latest** version from the committed image, if no default version is set, as before

**Prerequisites**:
- Admin user
- Test tool with at least two versions, none of them **latest**, and without settings of any version (e.g. an image pushed to the registry only as `<registry>/<group>/<tool>:<version>` and `...:<other>`, and registered as a tool). With a single version, that version is the default one already, and it has no button to set it as the default
- `<version>` is a version of the test tool
- If the tool scanning is enabled, the `security.tools.policy.deny.not.scanned` system preference is disabled, so that a version which is not scanned yet can be launched

**Preparations**:
1. Login as the admin user from the prerequisites
2. Set the `<version>` version as the default one of the test tool, as described in [4664_2](4664_2.md) (steps 1-4). If the **VIEW UNSCANNED VERSIONS** button is shown at the **VERSIONS** tab, click it first
3. Click the **SETTINGS** tab of the test tool. Specify a valid value for **Cmd template**, and click **SAVE**

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Open the **Tools** page | |
| 2 | Select the test tool from the prerequisites | |
| 3 | Click the **Run** button at the top of the tool page | |
| 4 | In an appeared pop-up window click **Launch** button | |
| 5 | At the **Runs** page, click the just-launched run | |
| 6 | Wait until the **COMMIT** hyperlink appears in the right upper corner, then click it | A pop-up with the header `Commit pipeline run` appears |
| 7 | In the **Docker image** field, select the test tool's registry and tools group, and make sure the tool name is the test tool's name | |
| 8 | Replace the value of the **Version** field with `default-commit-1` | |
| 9 | Click **COMMIT** button | The **COMMITTING...** label appears |
| 10 | Wait until the commit finishes | The label `COMMIT SUCCEEDED` with the commit date appears |
| 11 | Click the **CommitPipelineRun** task | The log window contains the row `[INFO] <registry>/<group>/<tool>:default-commit-1 tool has a default version set, latest version will not be created` |
| 12 | Open the **Tools** page, select the test tool. Click the **VERSIONS** tab, and if the **VIEW UNSCANNED VERSIONS** button is shown, click it | <li> The `default-commit-1` version is shown <li> There is no **latest** version <li> The `<version>` version has the **default** label |
| 13 | Click the `default-commit-1` version, click its **SETTINGS** tab | **Cmd template** is the one specified at step 3 of the preparations |
| 14 | Return to the test tool page, click the **VERSIONS** tab. Click the "filled star" button opposite the `<version>` version | The `<version>` version has no **default** label |
| 15 | Open the run launched at step 4. Repeat steps 6-10, with the `default-commit-2` value of the **Version** field | The label `COMMIT SUCCEEDED` with the commit date appears |
| 16 | Click the **CommitPipelineRun** task | The log window contains the row `[INFO] latest version created as <registry>/<group>/<tool>:latest` |
| 17 | Open the **Tools** page, select the test tool. Click the **VERSIONS** tab, and if the **VIEW UNSCANNED VERSIONS** button is shown, click it | <li> The `default-commit-2` and **latest** versions are shown with the same ***Digest*** <li> The **latest** version has the **default** label |

**After**:
- Stop the run launched at step 4
- Delete the `default-commit-1` and `default-commit-2` versions of the test tool. The **latest** version is deleted together with the `default-commit-2` one, since they are pushed from the same image
- Clear the settings of the `<version>` version saved at step 3 of the preparations
