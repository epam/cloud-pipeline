# [Manual] Notifications are removed after the configured storing period expires

Test verifies that old push notifications are automatically removed after the number of days configured in the `system.notifications.exp.period` system preference, and that setting the preference to blank disables automatic removal.

**Prerequisites**:
- Admin user
- Non-admin user (user1) with at least one existing read notification older than 1 day

| Steps | Actions | Expected results |
|:---:|------|---|
| 1 | Login as the admin user from the prerequisites | |
| 2 | Open **Settings** → **Preferences**. Find the preference **`system.notifications.exp.period`** | |
| 3 | Set the value to `1` (1 day) and save | The preference is saved |
| 4 | Wait until the next scheduled cleanup cycle runs (or advance the notification date in the test environment to simulate expiry) | |
| 5 | Login as user1. Open the **Notifications** section and switch to the **Read** list | Notifications older than 1 day are no longer present in the list |
| 6 | Login as admin. Set **`system.notifications.exp.period`** to blank (empty) and save | The preference is saved with no value |
| 7 | Verify that existing notifications are no longer automatically removed after the cleanup cycle | Notifications are retained indefinitely; no notifications are removed by the cleanup process |

**After**:
- Restore the original value of `system.notifications.exp.period`.
