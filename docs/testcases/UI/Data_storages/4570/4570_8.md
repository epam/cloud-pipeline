# [Negative] A storage that allows no downloads offers no "Download archive" either

Test verifies that:
- a **sensitive** storage offers no **Download archive** item for a selection, not even to the storage owner, and no folder in it carries a checkbox for a user who may only read it
- a storage whose download is restricted to other user groups offers no **Download archive** item either, even for a selected folder

**Prerequisites**:
- Admin user
- Non-admin user, without the **ROLE_STORAGE_READER** role, and in no group or role named `storage-downloaders`
- Data sharing is not configured on the deployment - the `data.sharing.base.api` system preference is empty. Otherwise every folder carries a checkbox for the **Share** action alone, whatever the user's permissions, and the folder-checkbox expectations below cannot be checked

**Preparations**:
1. Login as the admin user from the prerequisites
2. Open the **Settings** page, then the **PREFERENCES** tab. Click the **User Interface** tab, find the `ui.storage.download.attribute` preference, save its current value, then set it to `download_allowed_roles` and click **Save**
3. Create an object storage `sensitive-storage` with the "**Sensitive storage**" checkbox set
4. Open `sensitive-storage` and create a folder `folder1` and two files `testfile1.txt` and `testfile2.txt` in it
5. Give only allow **Read** permission on `sensitive-storage` to the non-admin user from the prerequisites
6. Create an object storage `restricted-storage`. Open it and create a folder `folder2` and two files `testfile3.txt` and `testfile4.txt` in it
7. Open the attributes of `restricted-storage` and add the attribute `download_allowed_roles` with the value `storage-downloaders`
8. Give allow **Write** permission on `restricted-storage` to the non-admin user from the prerequisites. Leave the admin user as the storage owner

| Steps | Actions | Expected results |
|:---:|---| --- |
| 1 | Login as the admin user from the prerequisites | |
| 2 | Open `sensitive-storage` | <li> `folder1`, `testfile1.txt` and `testfile2.txt` are listed <li> no file row has a **Download** button |
| 3 | Check the checkboxes next to `testfile1.txt` and `testfile2.txt` | The **2 items selected** button appears |
| 4 | Click the **2 items selected** button | The dropdown contains neither a **Download archive** item nor a **Download** item |
| 5 | Click on the checkbox next to the `folder1` name, so that the folder is selected as well | The **3 items selected** button appears |
| 6 | Click the **3 items selected** button | The dropdown still contains no **Download archive** item |
| 7 | Logout and login as the non-admin user from the prerequisites | |
| 8 | Open `sensitive-storage` from the library-tree | <li> `folder1` is listed <li> there is **no** checkbox next to the `folder1` name |
| 9 | Open `restricted-storage` from the library-tree | <li> `folder2`, `testfile3.txt` and `testfile4.txt` are listed <li> no file row has a **Download** button <li> there is a checkbox next to the `folder2` name - the user has **Write** on this storage |
| 10 | Check the checkboxes next to `folder2`, `testfile3.txt` and `testfile4.txt` | The **3 items selected** button appears |
| 11 | Click the **3 items selected** button | The dropdown contains neither a **Download archive** item nor a **Download** item |

**After**:
- As the admin user, delete `sensitive-storage` and `restricted-storage`
- Restore the `ui.storage.download.attribute` preference to the value saved at step 2 of Preparations
