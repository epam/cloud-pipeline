# A direct non-inherited permission on an object overrides an inherited permission from its parent

Test verifies that an **Allow** permission granted directly to a group on an object takes priority over
a **Deny** permission inherited from the parent folder, where that inherited **Deny** was granted
directly to the user on the parent.

**Prerequisites**:
- admin user
- non-admin user (`user1`)
- user group (`test_group_4110_4`) with `user1` added as a member

**Preparations**:
1. Login as the admin user from the prerequisites
2. Open the **Library** page
3. Hover over **+ Create v**, click **Folder**. Specify a valid folder name (`folder_4110_4`), click **OK**
4. Open `folder_4110_4`, click the gear icon in the upper-right corner, click **Edit folder**
5. In the pop-up that appears, click the **Permissions** tab
6. Click the **Add user** button. Enter `user1` from the prerequisites, click **OK**
7. In the list, click on `user1`. Set the checkboxes in the **Deny** column opposite **Read** and **Write**. Close the pop-up
8. Inside `folder_4110_4`, hover over **+ Create v**, click **Folder**. Specify a valid folder name (`subfolder_4110_4`), click **OK**
9. Open `subfolder_4110_4`, click the gear icon in the upper-right corner, click **Edit folder**
10. In the pop-up that appears, click the **Permissions** tab
11. Click the **Add group** button. Enter `test_group_4110_4` from the prerequisites, click **OK**
12. In the list, click on `test_group_4110_4`. Set the checkboxes in the **Allow** column opposite **Read** and **Write**
13. Close the pop-up

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Logout and login as `user1` from the prerequisites | |
| 2 | Open the **Library** page | `folder_4110_4` is not displayed in the tree |
| 3 | Click the search icon in the left menu panel (or press **Ctrl+F**) | The **Global_search** form appears |
| 4 | Click the **FOLDERS** button. Type `subfolder_4110_4` in the search query bar, press **Enter** | `subfolder_4110_4` is found and displayed in the search results |
| 5 | Click on `subfolder_4110_4` in the search results | The subfolder opens, no "Access is denied" error appears |
| 6 | Hover over **+ Create v**, click **Folder**. Specify a valid folder name (`subfolder_4110_4_child`), click **OK** | `subfolder_4110_4_child` is created successfully inside `subfolder_4110_4` |
