# A "Capacity retries" value is sent to the run as the CP_NODEUP_RETRY_COUNT parameter

Test verifies that
- a value set in the ***Capacity retries*** field is sent to the run as the `CP_NODEUP_RETRY_COUNT` parameter
- when the field is left empty, the run still gets `CP_NODEUP_RETRY_COUNT` set to the default (the `cluster.nodeup.retry.count` preference value)

**Prerequisites**:
- Admin user
- Test tool available in the registry
- Perform [4608_2](4608_2.md) case

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Open the **Tools** page | |
| 2 | Select the test tool from the prerequisites | |
| 3 | At the tool page, hover over the **Run v** button | |
| 4 | Click the **Custom settings** button in the list | |
| 5 | Expand the **Exec environment** section | |
| 6 | Input `7` into the ***Capacity retries*** field | |
| 7 | Click the **Launch** button | |
| 8 | In an appeared pop-up window click **Launch** button | |
| 9 | At the **Runs** page, click the just-launched run | |
| 10 | Expand the **Parameters** section | `CP_NODEUP_RETRY_COUNT: 7` is shown |
| 11 | Open the **Tools** page | |
| 12 | Select the test tool from the prerequisites | |
| 13 | At the tool page, hover over the **Run v** button | |
| 14 | Click the **Custom settings** button in the list | |
| 15 | Expand the **Exec environment** section | ***Capacity retries*** field is empty, with placeholder `N` |
| 16 | Click the **Launch** button, leaving ***Capacity retries*** field empty | |
| 17 | In an appeared pop-up window click **Launch** button | |
| 18 | At the **Runs** page, click the just-launched run | |
| 19 | Expand the **Parameters** section | `CP_NODEUP_RETRY_COUNT: N` is shown, where `N` is the placeholder value from step 15 |

**After**:
- Stop the runs launched at steps 7-8 and 16-17
