# Cancel on the upload confirmation pop-up discards the pending selection

Test verifies that:
- clicking **Cancel** on the **Upload files** pop-up closes it without uploading anything
- the storage listing is not refreshed by **Cancel** - nothing changed, so there is nothing to show
- picking a new batch right after works exactly as it would have if the pop-up had never opened

**Prerequisites**:
- A user with **READ** and **WRITE** permissions on an S3 object storage (or an NFS storage whose
  share is mounted as NFS)

**Preparations**:
1. Login as the user from the Prerequisites
2. Open the storage from the Prerequisites
3. On the local machine, have ready one archive file (e.g. `archive1.zip`) and one ordinary file
   (e.g. `file1.txt`)

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Note the files currently in the storage's current folder |  |
| 2 | Click the **Upload** button, select `archive1.zip` in the OS file dialog and confirm | The **Upload files** pop-up opens, listing `archive1.zip` with a zip icon, and the **Cancel**/**Upload and extract**/**Upload** buttons |
| 3 | Click **Cancel** | The pop-up closes immediately. The storage's file listing is unchanged - `archive1.zip` is not present |
| 4 | Wait a few seconds, then refresh the storage view manually | `archive1.zip` is still not present - **Cancel** did not queue or start any upload |
| 5 | Click the **Upload** button again, select `file1.txt` (no archive) in the OS file dialog and confirm | The file uploads immediately: no **Upload files** confirmation pop-up appears, since the new selection holds no archive. The ordinary **Uploading files...** progress pop-up appears and closes once the upload finishes |
| 6 | Look at the storage listing | `file1.txt` is present; `archive1.zip` is still not present |
