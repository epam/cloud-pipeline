# "Standard size" of an excluded NFS storage doesn't change after adding files and re-indexing

Test verifies that for an NFS storage excluded from file indexing by the `Billing status` = `Exclude` attribute, the **Standard size** shown on the storage page doesn't change after new files are added and the storage is re-indexed - because its files are no longer being added to the search index that this value is calculated from.

**Prerequisites**:
- admin user
- Non-empty NFS storage `nfs_storage3` registered on the platform, with at least one file already indexed (searchable)

**Preparations**:

1. Login as admin user from the prerequisites.
2. Open **Library** page.
3. Open `nfs_storage3`.
4. Click on **Show attributes** button in the right upper corner.
5. Click on **+ Add** button.
6. Select `Billing status` in the **_Key_** field and `Exclude` in the **_Value_** field. Click **Add** button.
7. Wait for the next NFS indexing cycle.

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Open `nfs_storage3` | **Standard size: ...** value is shown near the storage name |
| 2 | Note the current **Standard size** value | |
| 3 | Upload several new files into `nfs_storage3` | |
| 4 | Click **Re-index** control next to the **Standard size** value | A message that the storage size refresh has been requested is shown |
| 5 | Wait a couple of minutes and reopen `nfs_storage3` | **Standard size** value is the same as noted at step 2 - it isn't increased by the size of the files uploaded at step 3 |
