# "Upload and extract" uploads the batch, then queues extraction and closes

Test verifies that 
- choosing **Upload and extract** on the **Upload files** pop-up uploads every
picked file exactly like **Upload** would, then queues one extraction task per uploaded archive and tells the user where to follow them 
- the message's **Show storage tasks** is a clickable link that opens the **Storage tasks** window, and that each queued task is listed there as an **Extract archive** task, naming the folder it was queued from.

**Prerequisites**:
- A non-admin user with **READ** and **WRITE** permissions on an S3 object storage (or an NFS storage whose share is mounted as NFS)

**Preparations**:
1. Login as the user from the Prerequisites
2. Open the storage from the Prerequisites
3. On the local machine, have ready two archive files (e.g. `archive1.zip`, `archive2.tar.gz`) and
 one ordinary file (e.g. `file1.txt`)

| Steps | Actions | Expected results |
| :---: |---|---|
| 1 | Click the **Upload** button, select all three files from Preparations together in the OS file dialog and confirm | The **Upload files** pop-up opens, listing all three files by name only, and the **Cancel**/**Upload and extract**/**Upload** buttons |
| 2 | Look at the buttons the moment the pop-up opens | **Upload and extract** is briefly unavailable while the archive-task allowance is checked, then become available. **Cancel** is available throughout |
| 3 | Click **Upload and extract** | The pop-up switches to the progress view, titled **Uploading files...**, with a progress row per file same as an ordinary upload |
| 4 | Wait for all three files to finish uploading | <li> A loading message reading `Starting archive extraction...` appears briefly <li> It is replaced by a message reading `Extraction of 2 archives has been queued. Follow their progress under "Show storage tasks".`, where **Show storage tasks** rendered as a clickable link |
| 5 | Before the message disappears on its own, click the **Show storage tasks** link inside it | The message closes, and the **Storage tasks** window opens that contains <li> Two new rows are listed, one per uploaded archive <li> Each has **Extract archive** in the **Type** column <li> Each names its own archive - `archive1.zip` and `archive2.tar.gz` - with no item count in brackets after the name <li> Each shows a **Source** of `<storage name>/` - the folder the files were uploaded to <li> Each shows a `PENDING` or `RUNNUNG` **Status** <li> Each offers a **Cancel** button in the **Actions** column while it is pending or running |
| 6 | Wait for both tasks to finish. Close the **Storage tasks** window, then refresh the storage listing | <li> `file1.txt`, `archive1.zip` and `archive2.tar.gz` are all present <li> An `archive1/` and an `archive2/` folders have appeared beside them, each holding its archive's contents |

**After**:
- Delete `file1.txt`, `archive1.zip`, `archive2.tar.gz` and the `archive1/` and `archive2/` folders from the storage
