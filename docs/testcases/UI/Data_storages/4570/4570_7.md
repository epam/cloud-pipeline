# An archive download fails once the selection exceeds the `maxFilesCount` configured in `system.async.tasks.config`

Test verifies that:
- queuing an archive succeeds regardless of `maxFilesCount`, since the limit is counted once the
  task runs rather than when it is accepted
- once the task's own listing exceeds `maxFilesCount`, it finishes `FAILED` with a message naming
  the limit
- the failed task's **Status** cell shows that message on hover, and its **Actions** column offers
  no **Download** button

**Prerequisites**:
- Admin user
- A user with **READ** and **WRITE** permissions on an S3 object storage (or an NFS storage whose
  share is mounted as NFS), holding a folder with at least 3 files inside

**Preparations**:
1. Login as the admin user from the Prerequisites
2. Open the **Settings** page. Click the **PREFERENCES** tab, then the **Data storage** tab
3. Find the **`system.async.tasks.config`** preference and save its current value
4. Set its `tasks.storageDownloadAsArchive.maxFilesCount` field to `2`, keeping every other field
   as is. Click **Save**
5. Login as the user from the Prerequisites and open the storage from the Prerequisites

| Steps | Actions | Expected results |
| :---: |---| --- |
| 1 | Check the checkbox near the folder from Preparations | |
| 2 | Click the selection button (**"1 item selected"**) and choose **Download archive**, then click **OK** without changing the offered name | The notification `Archive download has been queued. Follow its progress under "Show storage tasks".` appears - the task is queued even though its listing has not been measured against `maxFilesCount` yet |
| 3 | Open the **Storage tasks** window (the grid-icon button at the top right of the storage view, then **Show storage tasks**) and wait until the task's status stops changing | The task's status becomes `FAILED` |
| 4 | Hover the **Status** cell of that row | A tooltip reading `The selection holds more than 2 files, which is the maximum one archive may contain. Ask for fewer folders at a time.` appears |
| 5 | Look at the **Actions** column of that row | No **Download** button is offered (the row is finished, so no **Cancel** button either) |

**After**:
- Restore the `system.async.tasks.config` preference to the value saved at step 3 of Preparations
