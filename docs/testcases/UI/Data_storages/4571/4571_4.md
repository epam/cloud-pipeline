# "Upload and extract" uploads the batch, then shows the extraction status before closing

Test verifies that choosing **Upload and extract** on the **Upload files** pop-up uploads every
picked file exactly like **Upload** would, and then shows a status line naming how many archives
are being extracted, closing the pop-up once that step finishes.

**_Note_**: extracting an archive's contents into the storage is not implemented on the server yet -
the button's upload half is real, but the extraction request it sends afterwards is answered by a
stand-in that always reports success after a short delay, without the platform doing anything. This
case only checks what the pop-up itself shows; it does **not** check for any extracted file
appearing in the storage, because that part of the feature does not exist yet.

**Prerequisites**:
- A user with **READ** and **WRITE** permissions on an S3 object storage (or an NFS storage whose
  share is mounted as NFS)

**Preparations**:
1. Login as the user from the Prerequisites
2. Open the storage from the Prerequisites
3. On the local machine, have ready two archive files (e.g. `archive1.zip`, `archive2.tar.gz`) and
   one ordinary file (e.g. `file1.txt`)

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Click the **Upload** button, select all three files from Preparations together in the OS file dialog and confirm | The **Upload files** pop-up opens, listing all three files - the two archives each with a zip icon - and the **Cancel**/**Upload and extract**/**Upload** buttons |
| 2 | Click **Upload and extract** | The pop-up switches to the progress view, titled **Uploading files...**, with a progress row per file - same as an ordinary upload |
| 3 | Wait for all three files to finish uploading | <li> The pop-up's title changes to **Extracting archives...** <li> Below the three finished rows, a line with a loading spinner reads `Extracting 2 archives...` <li> The pop-up cannot be closed while this is shown: there is no close cross, and pressing **Esc** or clicking outside the pop-up has no effect |
| 4 | Wait a few seconds | The status line and the pop-up disappear on their own; the storage listing refreshes |
| 5 | Look at the storage listing | `file1.txt`, `archive1.zip` and `archive2.tar.gz` are all present, each as the file that was uploaded. Out of scope for this case: whether their contents were extracted - the server does not implement that step yet, so no extracted files are expected to appear |

**After**:
- Delete `file1.txt`, `archive1.zip` and `archive2.tar.gz` from the storage
