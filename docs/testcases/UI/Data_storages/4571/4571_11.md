# An archive extraction fails before it is fetched once the archive itself exceeds `maxArchiveSizeBytes` configured in `system.async.tasks.config`

Test verifies that:
- queuing an extraction succeeds regardless of `maxArchiveSizeBytes`, since the limit is checked
 once the task runs rather than when it is accepted
- the worker checks the archive's own size from the storage listing before fetching a byte of it,
 so an oversized archive finishes `FAILED` straight away, with a message naming both sizes
- the failed task's **Status** cell shows that message on hover

**Prerequisites**:
- Admin user
- A user with **READ** and **WRITE** permissions on an S3 object storage (or an NFS storage whose
 share is mounted as NFS)

**Preparations**:
1. Login as the admin user from the Prerequisites
2. Open the **Settings** page. Click the **PREFERENCES** tab, then the **Data storage** tab
3. Find the **`system.async.tasks.config`** preference and save its current value
4. Set its `tasks.storageUnpackArchive.maxArchiveSizeBytes` field to `10`, keeping every other
 field as is. Click **Save**
5. Login as the user from the Prerequisites and open the storage from the Prerequisites
6. On the local machine, have ready one archive file at least 1 KB in size (e.g. `archive1.zip`)
7. Upload `archive1.zip` into the storage via **Upload** → **Upload**, so nothing is queued yet

| Steps | Actions | Expected results |
| :---: | --- |---|
| 1 | Select `archive1.zip` alone and click the selection button (**"1 item selected"**) | An **Extract archive** item is listed |
| 2 | Click **Extract archive** | A message confirms the extraction has been queued - the task is queued even though its own size has not been measured against `maxArchiveSizeBytes` yet |
| 3 | Open the **Storage tasks** window (the grid-icon button at the top right of the storage view, then **Show storage tasks**) and wait until the task's status stops changing | The task's status becomes `FAILED` |
| 4 | Hover the **Status** cell of that row | A tooltip reading `The archive is <size>, and 10 B is the largest one this platform extracts. Split it, or ask an administrator to raise the limit. Nothing was written to the destination.` appears, `<size>` being `archive1.zip`'s actual size |
| 5 | Look at the **Actions** column of that row | No **Download** button is offered (the row is finished, so no **Cancel** button either) |
| 6 | Look at the storage listing | No folder was created beside `archive1.zip` - the archive was refused before anything was extracted |

**After**:
- Delete `archive1.zip` from the storage
- Restore the `system.async.tasks.config` preference to the value saved at step 3 of Preparations
