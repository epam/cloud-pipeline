# Direct user permission has priority over Group and Role permissions

Test verifies that an **Allow** permission granted directly to a user takes priority over **Deny**
permissions granted to a group the user belongs to and to the `ROLE_USER` role, on the same object.

**Prerequisites**:
- admin user
- non-admin user (`user1`)
- user group (`test_group_4110_1`) with `user1` added as a member

**Preparations**:
1. Login as the admin user from the prerequisites
2. Open the **Library** page
3. Hover over **+ Create v**, click **Folder**. Specify a valid folder name (`folder_4110_1`), click **OK**
4. Open `folder_4110_1`, click the gear icon in the upper-right corner, click **Edit folder**
5. In the pop-up that appears, click the **Permissions** tab
6. Click the **Add user** button. Enter `user1` from the prerequisites, click **OK**
7. In the list, click on `user1`. Set the checkboxes in the **Allow** column opposite **Read** and **Write**
8. Click the **Add group** button. Enter `test_group_4110_1` from the prerequisites, click **OK**
9. In the list, click on `test_group_4110_1`. Set the checkboxes in the **Deny** column opposite **Read** and **Write**
10. In the list, click on `ROLE_USER` (listed by default for every object). Set the checkboxes in the **Deny** column opposite **Read** and **Write**
11. Close the pop-up

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Logout and login as `user1` from the prerequisites | |
| 2 | Open the **Library** page | `folder_4110_1` is visible in the tree |
| 3 | Click on `folder_4110_1` | The folder opens, no "Access is denied" error appears |
| 4 | Hover over **+ Create v**, click **Folder**. Specify a valid folder name (`subfolder_4110_1`), click **OK** | `subfolder_4110_1` is created successfully inside `folder_4110_1` |
