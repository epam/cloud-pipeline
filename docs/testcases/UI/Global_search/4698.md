# Search for files with paths longer than 512 bytes

Test verifies that:
- The files of an object storage are indexed when the storage holds files with paths longer than 512 bytes
- A file with a path longer than 512 bytes can be found via the Global search, and its preview shows the full path
- Scrolling through the Global search results shows each such file exactly once

**Prerequisites**:
- admin user
- `pipe` CLI configured for the admin user

**Preparations**:

1. Login as admin user from the prerequisites.
2. Open the **Library** page and create a new object storage `storage1` (AWS S3, GCS or Azure Blob).
3. Open `storage1` and create a file `short_path_file.txt` with some text content in its root.
4. Prepare a local folder `global_search_files` with 120 files `global_search_file_001.txt` ... `global_search_file_120.txt`, each with some text content.
5. Upload the folder content into `storage1`, under three nested folders `<long_folder>`, where `<long_folder>` is a folder name of 200 `a` characters:
   `pipe storage cp global_search_files s3://storage1/<long_folder>/<long_folder>/<long_folder>/ -r`
   (use `gs://` or `az://` for the other providers). The full path of each file is longer than 512 bytes.
6. Wait for the next indexing cycle of the storage files.

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Open the **Home** page and press `Ctrl+F` | The Global search form opens |
| 2 | Enter `short_path_file.txt` into the search query, press **Enter** | The list of the search results contains `short_path_file.txt` |
| 3 | Enter `global_search_file_001.txt` into the search query, press **Enter** | The list of the search results contains `global_search_file_001.txt` |
| 4 | Hover over the found `global_search_file_001.txt` item | A content panel appears, containing: <li>a header with the name `global_search_file_001.txt` <li>a label with the storage name `storage1` <li>a label with the full path of the file, including all three `<long_folder>` folders <li>the content of `global_search_file_001.txt` |
| 5 | Enter `global_search_file_*` into the search query, press **Enter** | The list of the search results contains files `global_search_file_*.txt` |
| 6 | Scroll the list of the search results down to its end, until no more results are loaded | Each of the files `global_search_file_001.txt` ... `global_search_file_120.txt` is shown in the list exactly once |
| 7 | Click on the found `global_search_file_001.txt` item | The page of `storage1` that contains `global_search_file_001.txt` opens |

**After**:
- Delete `storage1`
