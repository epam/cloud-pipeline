# Files can be removed from the upload confirmation pop-up before anything is uploaded

Test verifies that:
- every row of the **Upload files** pop-up carries a cross that drops that file from the batch
- a removed file is neither uploaded nor extracted
- the pop-up is unavailable for the moment the archive-task allowance check that follows a removal
 takes
- removing every archive leaves **Upload and extract** greyed out, while **Upload** still uploads
 what is left of the list
- removing the last file closes the pop-up, uploading nothing, exactly as **Cancel** does

**Prerequisites**:
- A non-admin user with **READ** and **WRITE** permissions on an S3 object storage (or an NFS storage whose
 share is mounted as NFS)

**Preparations**:
1. Login as the user from the Prerequisites
2. Open the storage from the Prerequisites
3. On the local machine, have ready two ordinary files (e.g. `file1.txt`, `file2.txt`) and two archive
 files (e.g. `archive1.zip`, `archive2.zip`)

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Click the **Upload** button, select all four files from Preparations together and confirm | The **Upload files** pop-up opens: <li> There is one row per selected file: `file1.txt`, `file2.txt`, `archive1.zip`, `archive2.zip` <li> Each row carries a cross on its right <li> **Cancel**, **Upload and extract** and **Upload** are shown at the bottom |
| 2 | Click the cross on the `file2.txt` row | <li> The `file2.txt` row disappears; the other three rows stay <li> For a moment the list is dimmed with a spinner over it and none of the three buttons can be clicked, while the archive-task allowance is checked again <li> All three buttons become available again |
| 3 | Click the cross on the `archive2.zip` row | The `archive2.zip` row disappears, leaving `file1.txt` and `archive1.zip` |
| 4 | Click **Upload and extract** and wait for the upload to finish | <li> Only `file1.txt` and `archive1.zip` are uploaded - the removed files are not in the storage <li> A message confirms that one extraction has been queued - singular, since one archive was left <li> An `archive1/` folder appears beside `archive1.zip`, holding its contents |
| 5 | Click the **Upload** button, select `archive1.zip` and `file2.txt` together and confirm | The **Upload files** pop-up opens, listing both files |
| 6 | Click the cross on the `archive1.zip` row | <li> The row disappears, leaving `file2.txt` <li> Once the allowance check is over, **Upload and extract** stays greyed out - there is no archive left to extract <li> **Upload** and **Cancel** are both clickable |
| 7 | Click **Upload** and wait for the upload to finish | <li> `file2.txt` is uploaded <li> No message about extraction appears |
| 8 | Click the **Upload** button, select `archive2.zip` alone and confirm | The **Upload files** pop-up opens, listing one row with a cross |
| 9 | Click the cross on that row | <li> The pop-up closes <li> `archive2.zip` is not uploaded: it is not in the storage listing <li> No message about extraction appears |

**After**:
- Delete `file1.txt`, `file2.txt`, `archive1.zip` and the `archive1/` folder from the storage
