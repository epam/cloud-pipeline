# Group permission has priority over Role permission

Test verifies that an **Allow** permission granted to a group takes priority over a **Deny** permission
granted to the `ROLE_USER` role, when the user has no permission entry of their own on the object.

**Prerequisites**:
- admin user
- non-admin user (`user1`)
- user group (`test_group_4110_2`) with `user1` added as a member

**Preparations**:
1. Login as the admin user from the prerequisites
2. Open the **Library** page
3. Hover over **+ Create v**, click **Folder**. Specify a valid folder name (`folder_4110_2`), click **OK**
4. Open `folder_4110_2`, click the gear icon in the upper-right corner, click **Edit folder**
5. In the pop-up that appears, click the **Permissions** tab
6. Click the **Add group** button. Enter `test_group_4110_2` from the prerequisites, click **OK**
7. In the list, click on `test_group_4110_2`. Set the checkboxes in the **Allow** column opposite **Read** and **Write**
8. In the list, click on `ROLE_USER` (listed by default for every object). Set the checkboxes in the **Deny** column opposite **Read** and **Write**
9. Close the pop-up

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Logout and login as `user1` from the prerequisites | |
| 2 | Open the **Library** page | `folder_4110_2` is visible in the tree |
| 3 | Click on `folder_4110_2` | The folder opens, no "Access is denied" error appears |
| 4 | Hover over **+ Create v**, click **Folder**. Specify a valid folder name (`subfolder_4110_2`), click **OK** | `subfolder_4110_2` is created successfully inside `folder_4110_2` |
