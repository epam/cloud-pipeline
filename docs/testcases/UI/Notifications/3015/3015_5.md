# [Manual] Notifications section displays unread and read lists with correct fields

Test verifies that the **Notifications** section accessible from the main menu shows all push notifications sent to the current user, with correct field values, and that the user can switch between the unread and read notification lists.

**Prerequisites**:
- Admin user
- Non-admin user (user1) with at least one unread and at least one previously read push notification

| Steps | Actions | Expected results |
|:---:|------|---|
| 1 | Login as user1 from the prerequisites | |
| 2 | Click the **Notifications** icon in the main menu | The **Notifications** section opens. By default, the **unread** notifications list is displayed |
| 3 | Inspect the notifications list columns | The list contains the following fields: **Status** (icon indicating unread/read), **Title**, **Text** (first line of the notification body), **Created date**, **Read date** |
| 4 | Verify that unread notifications have a distinct **Status** icon compared to read notifications | Unread and read notifications are visually distinguished by different icon colors in the **Status** column |
| 5 | Click the dropdown near the page title and select **Read** | The **Read** notifications list is shown |
| 6 | Inspect the read notifications list | Previously read notifications appear with correct **Status**, **Title**, **Text**, **Created date**, and **Read date** values |

**After**:
- No cleanup required.
