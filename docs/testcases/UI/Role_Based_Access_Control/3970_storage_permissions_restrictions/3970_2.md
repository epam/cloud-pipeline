# Storage permissions restrictions for all groups/roles

Test verifies that restrictions on permissions for storages  for all groups/roles can be specified using preference.

**Prerequisites**:
- admin user
- non-admin user (`user1`) with role `ROLE_STORAGE_MANAGER`
- test user group (`test_group`)
- Perform [3970_1](3970_1.md)

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Login as the admin user from the prerequisites | |
| 2 | Click the **PREFERENCES** tab | |
| 3 | Click the **User Interface** tab and find the `ui.storages.permissions.restrictions` preference | |
| 4 | Add to the `ui.storages.permissions.restrictions` preference json <br> `{` <br> `"role": "ALL",` <br> `"disable": "WRITE,EXECUTE"` <br> `}` | |
| 5 | Set *eye-icon* near the preference if they are disabled | |
| 6 | Click **Save** button. | | 
| 7 | Logout and login as the non-admin `user1` from the prerequisites | |
| 8 | Open `folder1` created at step 2 from the [3970_1](3970_1.md) case Preparations. | |
| 9 | Open the `storage1` created at step 3 from the [3970_1](3970_1.md) case Preparations. |  |
| 10 | Click gear-icon. In an appeared *Edit object storage* popup select *Permissions* tab | |
| 11 | Click the **Add group** button. Input the `ROLE_CONFIGURATION_MANAGER` role name. Click the **OK** button | |
| 12 | Click the appeared role at the *Groups and users* section | In the Permissions tab <li> *WRITE, EXECUTE* checkboxes are ticked as **DENY** and disabled. <li> *READ* permission empty in the both columns and active|
| 13 | Close *Edit group* popup | |

**After:**
- Restore the value of the `ui.storages.permissions.restrictions` preference to the initial value.
