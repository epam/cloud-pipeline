# Downloads window: clearing the Owner filter by hand, and "Reset to defaults"

Test verifies that:
- the **Owner** column's filter offers **OK** and **Reset to defaults**, and no **Clear** link
- an administrator who deletes the user name from the filter's field and confirms sees every user's tasks - the filter is not quietly restored to their own name
- **Reset to defaults** puts the filter back to the administrator's own user name
- the **Owner** column's filter icon is highlighted only while the filter names someone other than the signed-in user

**Prerequisites**:
- Admin user (or a user with the **ROLE_STORAGE_ADMIN** role)
- Non-admin user, without the **ROLE_STORAGE_ADMIN** role
- An S3 object storage (or an NFS storage whose share is mounted as NFS) both users can access, holding at least two files

**Preparations**:
1. Login as the non-admin user from the Prerequisites
2. Open the storage from the Prerequisites, select a file via its checkbox, click the selection button, choose **Download archive**, then click **OK** without changing the offered name
3. Logout, then login as the admin user from the Prerequisites
4. Open the same storage, select the other file, and queue an archive the same way
5. Open the **Downloads** window: click the grid-icon button at the top right of the storage view and choose **Show downloads**

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Look at the table | <li> There is an **Owner** column, with a filter icon on its own header <li> Only the admin user's own task, queued at step 4 of Preparations, is shown <li> The **Owner** column's filter icon is not highlighted |
| 2 | Click the filter icon on the **Owner** column's header | <li> The filter dropdown opens with an input field holding the admin user's own user name <li> Below it there are two links, **OK** and **Reset to defaults**, and no **Clear** link |
| 3 | Delete the user name from the field so that it is empty, then click **OK** | <li> The dropdown closes and the table reloads <li> Both tasks are now shown - the non-admin user's one from step 2 of Preparations as well as the admin's own - each with its owner's name in the **Owner** column <li> The **Owner** column's filter icon is highlighted <li> A **Reset filters** button appears above the table |
| 4 | Click the filter icon on the **Owner** column's header again | The field is empty - the cleared owner was kept, not replaced by the admin's own user name |
| 5 | Click **Reset to defaults** | <li> The dropdown closes and the table reloads <li> Only the admin user's own task is shown again <li> The **Owner** column's filter icon is no longer highlighted, and the **Reset filters** button disappears |
| 6 | Logout, login as the non-admin user from the Prerequisites, open the storage and open the **Downloads** window | <li> The table has no **Owner** column and no owner filter <li> Only that user's own task is shown |

**After**:
- Cancel both tasks queued in Preparations from the **Downloads** window of the user who owns each, or let them finish and discard the downloaded archives
