# A run on a standard pool gets CP_CAP_POOL_ID, a run on a plain instance type does not

Test verifies that:
- a run launched with a node type from the **Pools** group gets the `CP_CAP_POOL_ID` parameter with the pool ID, and runs on a node of that pool
- a run launched with the same instance type from its family group gets no `CP_CAP_POOL_ID` parameter
- a standard pool shows no CPU/RAM/GPU request fields

**Prerequisites**:
- Admin user
- Test tool available in the registry
- Pools from the Preparations of [4960_1](4960_1.md) case

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Open the **Cluster state** page, the **HOT NODE POOLS** tab | |
| 2 | Click `pool-standard-default` and save the `pool_id` value from the page URL | |
| 3 | Open the **Tools** page | |
| 4 | Select the test tool from the prerequisites | |
| 5 | At the tool page, hover over the **Run v** button | |
| 6 | Click the **Custom settings** button in the list | |
| 7 | Expand the **Exec environment** section | |
| 8 | In the ***Node type*** field, select the `pool-standard-default` entry of the **Pools** group | <li> The field shows the instance type with the `pool-standard-default` tag <li> No ***CPU request***, ***RAM request*** or ***GPU request*** fields are shown |
| 9 | Click the **Launch** button | |
| 10 | In an appeared pop-up window click **Launch** button | |
| 11 | At the **Runs** page, click the just-launched run | |
| 12 | Expand the **Parameters** section | `CP_CAP_POOL_ID` is shown, with the pool ID saved at step 2 |
| 13 | Wait until the **IP** label appears in the **Instance** section, and click the hyperlink near it | The node header has the label with the `pool-standard-default` name |
| 14 | Repeat steps 3-7 | |
| 15 | In the ***Node type*** field, select the instance type of `pool-standard-default` from its family group (with no tag) | |
| 16 | Repeat steps 9-11 | |
| 17 | Expand the **Parameters** section | `CP_CAP_POOL_ID` is not shown |

**After**:
- stop the runs launched at steps 10 and 16
