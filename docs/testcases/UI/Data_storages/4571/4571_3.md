# "Upload" on the confirmation pop-up uploads the archive as-is, without extracting it

Test verifies that choosing **Upload** on the **Upload files** pop-up uploads every picked file,
archive included, exactly as an upload worked before this pop-up existed - no extraction is
attempted, and the archive stays in the storage as its own file.

**Prerequisites**:
- A user with **READ** and **WRITE** permissions on an S3 object storage (or an NFS storage whose
  share is mounted as NFS)

**Preparations**:
1. Login as the user from the Prerequisites
2. Open the storage from the Prerequisites
3. On the local machine, have ready one archive file (e.g. `archive1.zip`) and one ordinary file
   (e.g. `file1.txt`)

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Click the **Upload** button, select both files from Preparations together in the OS file dialog and confirm | The **Upload files** pop-up opens, listing both files - `archive1.zip` with a zip icon - and the **Cancel**/**Upload and extract**/**Upload** buttons |
| 2 | Click **Upload** | <li> The pop-up switches to the ordinary progress view, titled **Uploading files...** <li> A progress row with a percentage appears for each of the two files <li> At no point does a line mentioning "Extracting" appear, and the title never changes to **Extracting archives...** |
| 3 | Wait for the upload to finish | The pop-up closes on its own. The storage listing refreshes |
| 4 | Look at the storage listing | Both `file1.txt` and `archive1.zip` are present, `archive1.zip` as the single archive file that was uploaded - its contents were not extracted into the storage |

**After**:
- Delete `file1.txt` and `archive1.zip` from the storage
