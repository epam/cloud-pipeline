# A stalled refresh of the package lists is stopped and tried once more

Test verifies that:
- an `apt-get update` of the Cloud Pipeline repo setup that hangs is stopped after `CP_PKG_MANAGER_UPDATE_TIMEOUT_SEC` seconds, and is tried once more
- the run log shows that the refresh was stopped
- the Cloud Pipeline apt repo is set up, and the run starts

**Prerequisites**:
- Admin user
- Test tool based on Ubuntu 22.04, available in the registry. The Cloud Pipeline apt repo exists for its version: a run of the tool with the default settings logs `Using apt repo <url>...` in its *Console* task
- The `launch.pre.common.commands` preference has no other command for Ubuntu that runs `apt-get` or `apt`: such a command would run into the hang before the Cloud Pipeline repo setup

**Preparations**:
1. Login as the admin user from the prerequisites
2. Open the **Settings** page
3. Click the **PREFERENCES** tab
4. Click the **Launch** tab
5. Find the `launch.pre.common.commands` preference
6. Save the preference value. Add the `test_apt_hang_once` entry below into the `pre_init` → `linux` → `ubuntu` → `default` object of the value if the value has a `pre_init` section, otherwise into its `linux` → `ubuntu` → `default` object, creating the missing levels. If the value is empty, input the JSON as it is:
   ```json
   {
     "linux": {
       "ubuntu": {
         "default": {
           "test_apt_hang_once": [
             "[ -z \"$TEST_APT_HANG_ONCE\" ] || echo 'APT::Update::Pre-Invoke {\"test -f /tmp/test-apt-hung || { touch /tmp/test-apt-hung; sleep 1800; }\";};' > /etc/apt/apt.conf.d/00test-apt-hang-once"
           ]
         }
       }
     }
   }
   ```
   The command does nothing in a run without the `TEST_APT_HANG_ONCE` parameter. In a run with it, the first `apt-get update` hangs for 30 minutes
7. Click **Save** button
