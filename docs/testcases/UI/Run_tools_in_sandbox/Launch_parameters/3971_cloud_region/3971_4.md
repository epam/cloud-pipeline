# Mount rules: check filter storages for cloud region in Launch confirmation

Test verifies that storages that aren't suitable for run's cloud region aren't shown  in Launch confirmation.

**Prerequisites**:
- admin user
- Perform [3971_1](3971_1.md)

**Preparations**
1. Login as admin user from the prerequisites
2. Open the **Settings** page >> **CLOUD REGIONS** tab
3. Select `region1` on the left panel >> In the **Mount rules:** section select option `Same region` for *Object storages* and *File storages*. Click **Save** button.
4. Select `region2` on the left panel >> In the **Mount rules:** section select option `None` for *Object storages* and *File storages*. Click **Save** button.

| Steps | Actions | Expected results |
| :---: |--- | --- |
| 1 | Open the **Tools** page. Select the test tool | |
| 2 | At the tool page, hover over the **Run v** button | |
| 3 | Select the ***Custom settings*** option in the list | |
| 4 | Expand ***Exec environment*** section | |
| 5 | Select `region1` for **Cloud Region** | |
| 6 | Click **Launch** button | *Launch confirmation* pop-up appears that contains: <li> `storage1` and `nfs_storage1` are shown and `storage2` is missing in the list  of storages in the `Please review the list of the mount points below and choose the data storage to be mounted:` field |
| 7 | Click **Cancel** button | |
| 8 | Select `region2` for **Cloud Region** | |
| 9 | Click **Launch** button | *Launch confirmation* pop-up appears that contains: <li> `storage1`, `nfs_storage1` and `storage2` are missing in the list  of storages in the `Please review the list of the mount points below and choose the data storage to be mounted:` field |

**After:**
- Restore the `region1` and `region2` settings to the initial condition.
