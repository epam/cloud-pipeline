# [MANUAL] The archive-task allowance: a batch queues what it can, and at the limit Upload and extract is disabled

Test verifies that:
- an **Upload and extract** batch needing more archive tasks than the user has allowance left queues
  as many archives as it can, and reports both halves of that outcome: one message naming how many
  of the archives were queued, and a second explaining what stopped the rest
- with the allowance fully used up, the confirmation pop-up disables **Upload and extract** and shows
  the reason, leaving **Upload** and **Cancel** working
- the allowance is shared with archive downloads rather than counted separately

**_Note_**: manual, because it needs the user sitting at - or just under - the limit the
`storage.archive.config` preference's `maxUserTasks` sets, which has to be arranged by an
administrator for the run rather than reached through the GUI.

**Prerequisites**:
- An administrator, to set the preference below
- A user with **READ** and **WRITE** permissions on an S3 object storage (or an NFS storage whose
  share is mounted as NFS)

**Preparations**:
1. As the administrator, set `maxUserTasks` in the `storage.archive.config` preference to `2`
2. Login as the user from the Prerequisites
3. Open the storage from the Prerequisites
4. On the local machine, have ready three archive files (e.g. `a1.zip`, `a2.zip`, `a3.zip`)
5. Select a folder in the storage, choose **Download archive** from the selection button, and
   confirm with **OK** - so one of the two allowed tasks is an archive *download*, not an extraction

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Click the **Upload** button, select `a1.zip`, `a2.zip` and `a3.zip` together and confirm | The **Upload files** pop-up opens, listing the three files and the **Cancel**/**Upload and extract**/**Upload** buttons |
| 2 | Click **Upload and extract** and wait for all three files to finish uploading | <li> All three files upload successfully <li> A message reads `Extraction of 1 of 3 archives has been queued. Follow its progress under "Show storage tasks".` <li> A second message reports the reason the rest were not queued, naming the number of archive tasks already in progress and the limit |
| 3 | Open the **Storage tasks** window | <li> The archive-download task from Preparations is listed <li> Exactly one **Extract archive** task is listed, not three <li> The two together are the whole allowance - so the allowance covers both kinds, rather than giving extraction its own |
| 4 | Look at the storage listing | `a1.zip`, `a2.zip` and `a3.zip` are all present: the files uploaded even though two of the three extractions were refused |
| 5 | With the two tasks from step 3 still in progress, click the **Upload** button, select `a1.zip` and confirm | <li> The **Upload files** pop-up opens <li> **Upload and extract** is greyed out and cannot be clicked <li> An informational message inside the pop-up gives the reason, naming the number of archive tasks already in progress and the limit <li> **Upload** and **Cancel** are both still clickable |
| 6 | Click **Upload** in that pop-up | `a1.zip` uploads as an ordinary upload, with no extraction queued and no message about extraction - being at the limit does not stop the files themselves being uploaded |
| 7 | Cancel both tasks in the **Storage tasks** window, then upload `a2.zip` via **Upload and extract** | <li> **Upload and extract** is clickable again, and the pop-up shows no informational message <li> A message reads `Archive extraction has been queued. Follow its progress under "Show storage tasks".` - singular, and with no second message, since there is now allowance for it |

**After**:
- Cancel every archive task left in the **Storage tasks** window
- Delete `a1.zip`, `a2.zip` and `a3.zip` from the storage
- As the administrator, put `maxUserTasks` back to its original value
