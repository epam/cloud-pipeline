# CP_NODEUP_RETRY_COUNT works as a regular parameter when `ui.launch.allow.nodeup.count` is off

Test verifies that with the `ui.launch.allow.nodeup.count` system preference disabled (default) 
- there is no dedicated ***Capacity retries*** field
- the `CP_NODEUP_RETRY_COUNT` parameter can be added and used like any other system parameter, without a reserved-name restriction or value validation
- at case of `CP_NODEUP_RETRY_COUNT` parameter value isn't positive integer the preference `cluster.nodeup.retry.count` is used instead.

**Prerequisites**:
- Admin user
- Test tool available in the registry
- Node type `type1` of rare compute instance type for the current Cloud Provider which launch attempt can lead to the exception of insufficient capacity of such node types for the Cloud Region


**Preparations**:
1. Login as the admin user from the prerequisites
2. Open the **Settings** page
3. Click the **PREFERENCES** tab
4. Find the `ui.launch.allow.nodeup.count` preference
5. Save the preference value, then uncheck *Enabled* checkbox for `ui.launch.allow.nodeup.count` preference if needed
6. Click **Save** button if needed
7. Find the `cluster.nodeup.retry.count` preference and save it
8. Click the **Launch** tab
9. Save the `launch.run.reschedule.enabled` preference value, then uncheck *Enabled* checkbox for `launch.run.reschedule.enabled` preference if needed. Click **Save** button if needed
10. Open the **Tools** page, select the test tool from the prerequisites
11. Click the **SETTINGS** tab
12. Expand the **EXECUTION ENVIRONMENT** section
13. Save the ***Allow reschedule to different region in case of insufficient capacity*** value, then select ***Not Configured*** option if needed. Click **SAVE** button if needed
