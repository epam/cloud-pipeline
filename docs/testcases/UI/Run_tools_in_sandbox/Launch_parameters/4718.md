# [MANUAL] Open the CP_VSCODE_WORKSPACE_DIR folder in VS Code on connect

Test verifies that:
- the `CP_VSCODE_WORKSPACE_DIR` system parameter is offered in the **Add system parameter** list
- on connect, the Cloud Pipeline VS Code extension opens the folder set in `CP_VSCODE_WORKSPACE_DIR`
- the extension opens the home folder instead, and shows a warning, if there is no folder at the `CP_VSCODE_WORKSPACE_DIR` path

**Prerequisites**:
- Non-admin user
- Test tool with a Linux OS
- VS Code with the Cloud Pipeline VS Code extension, signed in as the non-admin user
- The **`launch.system.parameters`** preference has the `CP_VSCODE_WORKSPACE_DIR` parameter

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Login as the non-admin user from the prerequisites | |
| 2 | Open the **Tools** page | |
| 3 | Select test tool from the prerequisites | |
| 4 | Launch a selected tool with **Custom settings** | |
| 5 | Expand the **Advanced** section | |
| 6 | Click the ***Add system parameter*** button | The `CP_VSCODE_WORKSPACE_DIR` parameter is in the list, with the description *Absolute path to the folder the VS Code extension opens on connect, instead of the home folder. Used only if the user who connects can open the folder.* |
| 7 | Select the `CP_VSCODE_WORKSPACE_DIR` row in the list and click the **OK** button | |
| 8 | Set `/opt` as the value of the `CP_VSCODE_WORKSPACE_DIR` parameter | |
| 9 | Click **Launch** button | |
| 10 | In an appeared pop-up window click **Launch** button | Run appears on **ACTIVE RUNS** tab |
| 11 | In VS Code, open the Cloud Pipeline view, and wait until the run from step 10 is ready for SSH | |
| 12 | Select **Connect via SSH (Remote)** in the context menu of the run | A new VS Code window opens and connects to the run. The **Explorer** shows the `/opt` folder |
| 13 | Open a terminal in the remote window and run `pwd` | The output is `/opt` |
| 14 | Close the remote window, and select **Stop SSH Tunnel** for the run | |
| 15 | Repeat steps 2-7 | |
| 16 | Set `/opt/missing-folder-4718` as the value of the `CP_VSCODE_WORKSPACE_DIR` parameter | |
| 17 | Repeat steps 9-11 for the new run, then select **Connect via SSH (Remote)** in the context menu of the new run | <li> In the VS Code window where the connect was started, a warning appears: `CP_VSCODE_WORKSPACE_DIR of run <run_id> (/opt/missing-folder-4718) is not opened for <user>: it is not a folder this user can open. The home folder opens.`, where `<run_id>` is the ID of the new run, and `<user>` is the user VS Code connects as <li> A new VS Code window opens and connects to the run. The **Explorer** shows the home folder of `<user>`, not `/opt/missing-folder-4718` |

**After**:
- Close the remote window, and stop the SSH tunnel
- Stop the runs launched at steps 10 and 17
