# [Negative] The upload confirmation pop-up is not offered outside AWS S3 and NFS-mounted-NFS storages

Test verifies that the **Upload files** confirmation pop-up - and the choice between **Upload** and
**Upload and extract** - is only ever offered on an AWS S3 storage or an NFS storage whose share is
mounted as NFS. On any other storage type, and on an omics (sequence) store, picking a batch that
holds an archive uploads it right away, exactly like a batch with no archive.

**Prerequisites**:
- A user with **READ** and **WRITE** permissions on one of:
  - an Azure or a GCP storage, or
  - an NFS storage whose share is mounted as SMB or Lustre (not NFS), or
  - an omics (sequence) store

**Preparations**:
1. Login as the user from the Prerequisites
2. Open the storage from the Prerequisites
3. On the local machine, have ready one archive file (e.g. `archive1.zip`)

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Click the **Upload** button, select `archive1.zip` in the OS file dialog and confirm | A pop-up titled **Uploading files...** opens straight away, with a progress row for `archive1.zip`. The **Cancel**/**Upload and extract**/**Upload** choice never appears, regardless of `archive1.zip` being an archive |
| 2 | Wait for the upload to finish | The pop-up closes on its own |
| 3 | Look at the storage listing | `archive1.zip` is present, uploaded as-is |

**After**:
- Delete `archive1.zip` from the storage
