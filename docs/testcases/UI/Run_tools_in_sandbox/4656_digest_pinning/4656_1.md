# Docker image digest pinning is disabled by default

Test verifies that
- the `launch.docker.image.pin.digest` system preference is shown in the **Launch** group of the system preferences and is disabled by default
- a run launched while the preference is disabled has no ***Docker image digest*** in its **Instance** details, so its pod pulls the docker image by the tag, as before

**Prerequisites**:
- Admin user
- Test tool available in the registry
- The `launch.docker.image.pin.digest` preference has not been changed on the deployment. Otherwise, skip the default value check at step 4, save the preference value, and uncheck the preference's *Enabled* checkbox before step 5

**Preparations**:
1. Login as the admin user from the prerequisites

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Open the **Settings** page | |
| 2 | Click the **PREFERENCES** tab | |
| 3 | Click the **Launch** tab | |
| 4 | Find the `launch.docker.image.pin.digest` preference | <li> The preference is shown <li> Its *Enabled* checkbox is unchecked |
| 5 | Open the **Tools** page | |
| 6 | Select the test tool from the prerequisites | |
| 7 | Click the **Run** button | |
| 8 | In an appeared pop-up window click **Launch** button | |
| 9 | At the **Runs** page, click the just-launched run | |
| 10 | Wait until the run's state turns to **Running** | |
| 11 | Click the **Instance** item | <li> ***Docker image*** field is shown with the test tool's docker image name and tag <li> ***Docker image digest*** field isn't shown |

**After**:
- Stop the run launched at step 8
- Restore the `launch.docker.image.pin.digest` preference value, if it was saved and changed before step 5
