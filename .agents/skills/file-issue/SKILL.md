# Filing an issue

Read `.github/ISSUE_TEMPLATE/` and pick the file whose `about:` matches the issue you're filing — e.g. a
bug matches `bug_report.md`, a feature request matches `enhancement.md` — then follow its structure,
title and labels rather than inventing your own. Skip a section the issue genuinely has nothing for
rather than leaving the placeholder text in.

A followup or sub-issue found mid-task still uses the matching template, linked to its parent —
`CONTRIBUTIONS.md` → "Task entity properties" has the convention.

Attended: confirm the title and label with whoever asked before creating it — this is visible to the
whole team the moment it exists. Unattended: create it, and say so in the hand-back with the issue
number and URL.
