# "Upload and extract" uploads the batch, then queues extraction and closes

Test verifies that choosing **Upload and extract** on the **Upload files** pop-up uploads every
picked file exactly like **Upload** would, then queues the extraction of the uploaded archives as a
background task and tells the user where to follow it, closing the pop-up the same way an ordinary
upload closes - it does not stay open waiting for the extraction to run. It also verifies that the
message's **Show storage tasks** wording is a clickable link that opens the **Storage tasks**
window.

**_Note_**: extracting an archive's contents into the storage is not implemented on the server yet,
and the **Storage tasks** window does not list an extraction task today - only archive-download
tasks appear there. This case only checks what the GUI itself does: the two messages, the link, and
the pop-up closing. It does **not** check for an extraction entry appearing in the **Storage tasks**
window, and does **not** check for any extracted file appearing in the storage, because neither part
of the feature exists yet.

**Prerequisites**:
- A user with **READ** and **WRITE** permissions on an S3 object storage (or an NFS storage whose
  share is mounted as NFS)

**Preparations**:
1. Login as the user from the Prerequisites
2. Open the storage from the Prerequisites
3. On the local machine, have ready two archive files (e.g. `archive1.zip`, `archive2.tar.gz`) and
   one ordinary file (e.g. `file1.txt`)

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Click the **Upload** button, select all three files from Preparations together in the OS file dialog and confirm | The **Upload files** pop-up opens, listing all three files by name only, and the **Cancel**/**Upload and extract**/**Upload** buttons |
| 2 | Click **Upload and extract** | The pop-up switches to the progress view, titled **Uploading files...**, with a progress row per file - same as an ordinary upload |
| 3 | Wait for all three files to finish uploading | <li> A loading message reading `Starting archive extraction...` appears briefly <li> It is replaced by a message reading `Archive extraction has been queued. Follow its progress under "Show storage tasks".`, with **Show storage tasks** rendered as a clickable link <li> At no point does the pop-up's title change to anything about extracting, and no status line about extraction appears inside the pop-up itself |
| 4 | Before the message disappears on its own, click the **Show storage tasks** link inside it | The message closes, and the **Storage tasks** window opens |
| 5 | Close the **Storage tasks** window and look at the pop-up | The pop-up has closed on its own, the same way an ordinary upload's pop-up closes |
| 6 | Look at the storage listing | `file1.txt`, `archive1.zip` and `archive2.tar.gz` are all present, each as the file that was uploaded |

**After**:
- Delete `file1.txt`, `archive1.zip` and `archive2.tar.gz` from the storage
