# Removing an archive brings the batch back under the archive-task allowance

Test verifies that a batch needing more archive tasks than the user has allowance left is cut down in
the **Upload files** pop-up itself: removing an archive re-checks the allowance, the reason
disappears and **Upload and extract** becomes available, without closing the pop-up and picking the
files afresh.

**Prerequisites**:
- An admin user
- A non-admin user with **READ** and **WRITE** permissions on an S3 object storage (or an NFS storage whose
 share is mounted as NFS)

**Preparations**:
1. As the administrator, set `maxUserTasks` in the `system.async.tasks.config` preference to `2`
2. Login as the user from the Prerequisites
3. Open the storage from the Prerequisites
4. On the local machine, have ready three archive files (e.g. `a1.zip`, `a2.zip`, `a3.zip`)

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Click the **Upload** button, select `a1.zip`, `a2.zip` and `a3.zip` together and confirm | <li> The **Upload files** pop-up opens, listing the three files, each row with a cross <li> **Upload and extract** is disabled <li> An informational message `3 archives are selected, and you may start only 2 more archive tasks right now. Wait for one of your archive tasks to finish, or cancel one.` is shown inside the pop-up |
| 2 | Click the cross on the `a3.zip` row | <li> The `a3.zip` row disappears <li> The list is dimmed with a spinner over it while the allowance is checked again <li> Once that is over, the informational message is gone and **Upload and extract** is available |
| 3 | Click **Upload and extract** and wait for the upload to finish | <li> `a1.zip` and `a2.zip` are uploaded; `a3.zip` is not in the storage <li> A message reads that the extraction of 2 archives has been queued <li> The **Storage tasks** window lists two **Extract archive** tasks |

**After**:
- Delete `a1.zip`, `a2.zip` and the `a1/` and `a2/` folders from the storage
- As the administrator, put `maxUserTasks` back to its original value
