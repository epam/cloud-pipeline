# The per-user archive-download task cap blocks queueing

Test verifies that once a user has as many archive-download tasks in progress as the `maxUserTasks`
value of the `storage.download.archive.config` preference allows, queueing another one is blocked
with a message, both when clicking **Download archive** and when confirming the name pop-up, until
one of the in-progress tasks finishes or is cancelled.

**Prerequisites**:
- Admin user
- An AWS S3 object storage with several files exists

**Preparations**:
1. Login as the admin user from the prerequisites
2. Open the **Settings** page, then the **PREFERENCES** tab
3. Click the **Data storage** tab, find the `storage.download.archive.config` preference
4. Save its current value, then set its `maxUserTasks` field to `1`
5. Click **Save**

| Steps | Actions | Expected results |
| :---: |---| --- |
| 1 | Open the storage from the prerequisites | |
| 2 | Select 2 files, click the **2 items selected** button, click **Download archive**, then click **OK** without changing the name | The archive download is queued |
| 3 | Click the **2 items selected** button again, then click **Download archive** | The pop-up does not open; a message appears reading `You already have 1 archive downloads in progress, and the limit is 1. Wait for one to finish before starting another.` No task is queued |
| 4 | Open the **Downloads** window via the grid-icon button's **Show downloads** item, and wait until the task from step 2 finishes | |
| 5 | Click the **2 items selected** button, then click **Download archive** | The pop-up opens, since no task is currently in progress |
| 6 | Without closing that pop-up, open the same storage in a second browser tab, signed in as the same admin user | |
| 7 | In the second tab, select 2 files, click the **2 items selected** button, click **Download archive**, then click **OK** | The archive download is queued from the second tab |
| 8 | Switch back to the first tab and click **OK** in the pop-up still open from step 5 | The pop-up closes; the same blocking message as in step 3 appears, now counting the task queued at step 7; no task is queued from the first tab |
| 9 | In either tab, open the **Downloads** window and wait until the task queued at step 7 finishes | |
| 10 | Repeat step 5, then click **OK** | The archive download is queued |

**After**:
- Restore the `storage.download.archive.config` preference to the value saved at step 4 of Preparations
