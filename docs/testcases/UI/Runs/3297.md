# A run keeps its unavailable node for the grace period, and the node is marked unavailable

Test verifies that:
- a run whose node stops reporting to Kubernetes keeps running, while the node is unavailable for less than the `cluster.node.unavailable.grace.period.minutes` period
- the run gets the `NODE_UNAVAILABLE` tag and its date tag, and the ***NodeAvailabilityMonitor*** task of the run logs since when the node has been unavailable
- when the node reports again, the tag is removed, and the task logs since when the node has been available

**Prerequisites**:
- Admin user
- Test tool, e.g. `library/centos`
- Access to the nodes of the runs over SSH, as a user that can run `sudo systemctl` there, e.g. from the cluster master node with the SSH key of the nodes
- The `cluster.node.unavailable.grace.period.minutes` preference is at least `15` (default: `30`). The platform terminates the node of a run that stays unavailable longer, and the case keeps the node unavailable for up to about 10 minutes
- The `system.run.tag.date.suffix` preference is not empty (default: `_date`): without it, the run gets no date tag
- The test tool does not set the `NODE_UNAVAILABLE_GRACE_PERIOD_MINUTES` parameter: it overrides the preference for a run

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Login as the admin user from the prerequisites | |
| 2 | Open the **Tools** page | |
| 3 | Select the test tool | |
| 4 | Click **Run**. In the pop-up that appears, click **Set ON-DEMAND price type** if it is shown, then click **Launch** | |
| 5 | At the **Runs** page, click the just-launched run. Wait until the **SSH** hyperlink appears | |
| 6 | Expand the **Instance** section. Save the node name and the IP address of the **IP** row: `<node name> (<IP address>)` | |
| 7 | Log in to the node over SSH by the IP address saved at step 6 | |
| 8 | Optionally, start a timer that starts the kubelet again after 10 minutes, in case the case is interrupted: `sudo systemd-run --unit=kubelet-restore --on-active=600 /usr/bin/systemctl start kubelet` | |
| 9 | Stop the kubelet: `sudo systemctl stop kubelet`. Save the time (UTC) | `systemctl is-active kubelet` prints `inactive` |
| 10 | Go back to the page of the run. Refresh it until the ***NodeAvailabilityMonitor*** task appears, up to 5 minutes. Kubernetes marks the node unavailable about 40 seconds after the kubelet stops, and the platform checks the nodes every `cluster.autoscale.rate` milliseconds (`40000` by default) | |
| 11 | Click the ***NodeAvailabilityMonitor*** task | The log contains `Node <node name> has been unavailable since <time>`, where: <li> `<node name>` is the node name saved at step 6 <li> `<time>` is in the `yyyy-MM-dd HH:mm:ss.SSS` format, UTC, not earlier than the time saved at step 9, and not more than about 3 minutes after it |
| 12 | Expand the **Instance** section | <li> The run has the **Running** status <li> The **Tags** row has the `NODE_UNAVAILABLE` tag |
| 13 | Hover over the `NODE_UNAVAILABLE` tag | A pop-up shows how long the node has been unavailable, counted from the `<time>` of step 11, e.g. `Less than a minute` or `2 minutes` |
| 14 | Open the API method `/pipeline/restapi/run/<run ID>` in a new browser tab | The `tags` of the run have: <li> `"NODE_UNAVAILABLE": "true"` <li> the date tag `"NODE_UNAVAILABLE<suffix>": "<time>"`, where `<suffix>` is the value of the `system.run.tag.date.suffix` preference and `<time>` is the one of step 11 |
| 15 | On the node, start the kubelet again: `sudo systemctl start kubelet`. If the timer of step 8 was started, stop it: `sudo systemctl stop kubelet-restore.timer` | `systemctl is-active kubelet` prints `active` |
| 16 | Go back to the page of the run. Refresh it until the ***NodeAvailabilityMonitor*** task log has a new line, up to 5 minutes | The log contains `Node <node name> has been available since <time>`, where `<time>` is not earlier than the `<time>` of step 11 |
| 17 | Expand the **Instance** section | <li> The run has the **Running** status <li> The **Tags** row has no `NODE_UNAVAILABLE` tag |

**After**:
- Stop the run launched at step 4, and terminate its node at the **Cluster state** page
