# The latest version is the default one until a default version is set

Test verifies that
- while a default version is not set for a tool, its **latest** version is marked as the default one
- the "Set as default" control is not shown for the **latest** version then, but is shown for the other versions
- the **Run** button at the top of the tool page launches the **latest** version

**Prerequisites**:
- Admin user
- Test tool with the **latest** version and at least two other versions, without a default version set

**Preparations**:
1. Login as the admin user from the prerequisites

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Open the **Tools** page | |
| 2 | Select the test tool from the prerequisites | |
| 3 | Click the **VERSIONS** tab | <li> The **latest** version has the **default** label <li> No other version has the **default** label |
| 4 | Hover over the **default** label | Tooltip `A default version is not set, so the latest version is used` appears |
| 5 | Look at the buttons opposite the **latest** version | There is no "star" button |
| 6 | Hover over the "star" button opposite any other version | Tooltip `Set as default` appears |
| 7 | Click the **Run** button at the top of the tool page | |
| 8 | In an appeared pop-up window click **Launch** button | |
| 9 | At the **Runs** page, click the just-launched run | |
| 10 | Click the **Instance** item | ***Docker image*** field is shown with the test tool's docker image and the `latest` tag |

**After**:
- Stop the run launched at step 8
