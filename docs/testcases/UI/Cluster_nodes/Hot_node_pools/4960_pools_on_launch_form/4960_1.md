# "Pools" group in the Node type list of the launch form

Test verifies that:
- the ***Node type*** list starts with a **Pools** group with every active node pool of the current region
- each pool is shown as the instance type with a tag holding the pool name
- the tag of a future-dated pool is blue, the tag of a default pool is not
- a pool of another region is not listed
- the plain instance types are still listed in their family groups

**Prerequisites**:
- Admin user
- Test tool available in the registry

**Preparations**:
1. Open the **Cluster state** page, the **HOT NODE POOLS** tab
2. In the default region, create four pools with different instance types, each with at least one node:
    - `pool-standard-default`: _Default_ mode, _Standard_ pool type
    - `pool-standard-future`: _Future dated_ mode, _Standard_ pool type
    - `pool-shareable-default`: _Default_ mode, _Shareable node_ pool type, with CPU and RAM requests enabled
    - `pool-shareable-future`: _Future dated_ mode, _Shareable node_ pool type, with CPU and RAM requests enabled
3. In another region, create `pool-other-region`: _Default_ mode, _Standard_ pool type
4. Wait until every pool is active (the future-dated pools need an active reservation)
