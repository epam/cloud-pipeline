# Credit transaction events are recorded in the audit trail

Test verifies that every change to a user's Platform Usage Credits balance is recorded as an event in the audit trail, including the timestamp, affected user, triggering rule, and a descriptive message.

**Prerequisites**:
- admin user
- non-admin user (user1)
- an active credit deduction rule (e.g. `Idle Run Penalty`: deduct 100 credits after 48 hours idle)
- Platform Usage Credits feature enabled

**Preparations**:
1. Login as the admin user from the prerequisites
2. Ensure user1 has a non-zero credit balance (e.g. `2000`)
3. Ensure the deduction rule from the prerequisites is enabled

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Login as the admin user from the prerequisites | |
| 2 | Open the **Settings** page. Navigate to the **Platform Usage Credits** → **Events** (or **Audit trail**) section | The events list is displayed |
| 3 | Apply a manual credit adjustment to user1 (e.g. deduct 100 credits with message `Manual test deduction`) | |
| 4 | Return to the **Events** section | A new event record appears for user1 |
| 5 | Inspect the new event record | The event contains: user1's name, the credit change amount (`-100`), a timestamp, and the message `Manual test deduction` |
| 6 | Login as user1 and navigate to the credit events/history page (if accessible to non-admin) | user1 can view their own credit event history and the manual deduction event is listed |

**After**:
- Restore user1's credit balance to the original value.
