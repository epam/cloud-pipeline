# Node pools in the launch confirmation dialog

Test verifies that when a tool has no default node type:
- the launch confirmation dialog lists the **Pools** group in its node type field
- a shareable pool shows the CPU/RAM/GPU request fields in the dialog
- the run gets `CP_CAP_POOL_ID` and the `CP_CAP_REQUESTS_*` parameters with the values set in the dialog

**Prerequisites**:
- Admin user
- A test tool with no ***Instance type*** set in its **SETTINGS**
- Pools from the Preparations of [4960_1](4960_1.md) case

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Open the **Cluster state** page, the **HOT NODE POOLS** tab | |
| 2 | Click `pool-shareable-future` and save the `pool_id` value from the page URL | |
| 3 | Open the **Tools** page | |
| 4 | Select the test tool from the prerequisites | |
| 5 | Click the **Run** button | The launch confirmation dialog shows `You should select instance type:` with a node type field |
| 6 | Click the node type field | The list starts with the **Pools** group, as at step 7 of [4960_1](4960_1.md) case |
| 7 | Select the `pool-shareable-future` entry | The ***CPU request*** and ***RAM request*** fields are shown under the node type field |
| 8 | Set `2` in the ***CPU request*** field | |
| 9 | Click the **Launch** button in the dialog | |
| 10 | At the **Runs** page, click the just-launched run | |
| 11 | Expand the **Parameters** section | <li> `CP_CAP_POOL_ID` is shown, with the pool ID saved at step 2 <li> `CP_CAP_REQUESTS_CPU` is `2` |
| 12 | Repeat steps 3-6 | |
| 13 | Select the `pool-standard-default` entry | No request fields are shown |
| 14 | Select a plain instance type from a family group | No request fields are shown |
| 15 | Click **Cancel** | |

**After**:
- stop the run launched at step 9
