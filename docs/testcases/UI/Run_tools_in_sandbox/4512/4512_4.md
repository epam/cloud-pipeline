# IDLE tag disappears when at least one of the activity type appears

Test verifies that IDLE tag disappears when at least one of the activity type appears.

**Prerequisites**:
- Admin user
- Test tool available in the registry that can run on a GPU instance type
- GPU instance available in the cloud region

**Preparations**:
1. Login as the admin user from the prerequisites.
2. Save the `system.idle.monitoring.config` system preference value.
3. Set `system.idle.monitoring.config` system preference value to:

```
[
 {
 "type": "CPU",
  "enabled": true,
  "thresholdPercent": 60,
  "gracePeriodMinutes": 5,
  "actionTimeoutMinutes": 10,
 `"action": "NOTIFY"
 },
 {
 "type": "GPU",
  "enabled": true,
  "gracePeriodMinutes": 5,
  "actionTimeoutMinutes": 10,
  "action": "NOTIFY"
 },
 {
  "type": "ABSOLUTE",
  "enabled": true,
  "actionTimeoutMinutes": 15,
  "action": "NOTIFY"
 }
]
```

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Open the **Tools** page | |
| 2 | Select the test tool from the prerequisites | |
| 3 | Launch the tool on a GPU instance type with default settings | |
| 4 | At the **Runs** page, click the just-launched run | |
| 5 | Wait until ***IDLE_GPU***, ***IDLE_CPU*** and ***IDLE*** tags appear in the **Instance** section | |
| 6 | Click the **SSH** hyperlink | |
| 7 | In the opened tab, enter and perform following commands to load CPU: <br> `sudo dnf config-manager --set-enabled powertools` <br> `sudo dnf install epel-release -y` <br> `sudo dnf install stress -y` <br> `sudo stress --cpu 4 --io 2 --vm 2 --vm-bytes 256M --timeout 1200s` |
| 8 | Close the tab | |
| 9 | Wait until ***IDLE_CPU*** tag disappears from the **Instance** section |  ***IDLE*** tag disappears from the **Instance** section simultaneously with ***IDLE_CPU*** tag |

**After**:
- Stop the run launched at step 3
- Restore the original values of `system.idle.monitoring.config`.
