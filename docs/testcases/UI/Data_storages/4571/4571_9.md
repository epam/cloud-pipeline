# [MANUAL] The archive-task allowance governs Upload and extract, and frees up on its own

Test verifies that:
- one archive is one task, so a batch needing more archive tasks than the user has allowance left
  makes **Upload and extract** unavailable, with the reason shown in the pop-up and naming both the
  number of archives selected and the number of tasks still allowed
- **Upload** and **Cancel** keep working while it is unavailable - being at the limit stops the
  extraction, not the upload
- the allowance is shared with archive downloads rather than counted separately
- the pop-up keeps checking while it is open, so freeing a slot makes the button available again
  without closing the pop-up and picking the files afresh

**_Note_**: manual, because it needs the user sitting at - or just under - the limit the
`system.async.tasks.config` preference's `maxUserTasks` sets, which has to be arranged by an
administrator for the run rather than reached through the GUI.

**Prerequisites**:
- An administrator, to set the preference below
- A user with **READ** and **WRITE** permissions on an S3 object storage (or an NFS storage whose
  share is mounted as NFS)

**Preparations**:
1. As the administrator, set `maxUserTasks` in the `system.async.tasks.config` preference to `2`
2. Login as the user from the Prerequisites
3. Open the storage from the Prerequisites
4. On the local machine, have ready three archive files (e.g. `a1.zip`, `a2.zip`, `a3.zip`)
5. Select a folder in the storage, choose **Download archive** from the selection button, and
   confirm with **OK** - so one of the two allowed tasks is an archive *download*, not an extraction

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Click the **Upload** button, select `a1.zip`, `a2.zip` and `a3.zip` together and confirm | <li> The **Upload files** pop-up opens, listing the three files <li> **Upload and extract** is greyed out and cannot be clicked: three archives need three tasks and only one is left <li> An informational message inside the pop-up gives the reason, naming both `3 archives` and the one task still allowed <li> **Upload** and **Cancel** are both clickable |
| 2 | Click **Upload** in that pop-up | All three files upload as an ordinary upload, with no extraction queued and no message about extraction - being at the limit does not stop the files themselves being uploaded |
| 3 | Delete `a2.zip` and `a3.zip` from the storage, then click **Upload**, select `a1.zip` alone and confirm | <li> The **Upload files** pop-up opens <li> **Upload and extract** is available: one archive needs one task, and one is left <li> No informational message is shown |
| 4 | Click **Cancel**, then queue a second archive download from the selection button so that both allowed tasks are in progress | The **Storage tasks** window lists two active tasks |
| 5 | Click **Upload**, select `a1.zip` alone and confirm | <li> **Upload and extract** is greyed out <li> The pop-up's message names the number of archive tasks already in progress and the limit - the allowance covers downloads and extractions together, so two downloads use it all up |
| 6 | Leaving that pop-up open, cancel one of the two tasks in the **Storage tasks** window, and wait a few seconds without touching the pop-up | <li> **Upload and extract** becomes available on its own <li> The informational message disappears <li> Neither the pop-up nor the file selection had to be re-made |
| 7 | Click **Upload and extract** and wait for the upload to finish | A message reads `Archive extraction has been queued. Follow its progress under "Show storage tasks".` - singular, with no second message, since there is now allowance for it |

**After**:
- Cancel every archive task left in the **Storage tasks** window
- Delete `a1.zip` from the storage
- As the administrator, put `maxUserTasks` back to its original value
