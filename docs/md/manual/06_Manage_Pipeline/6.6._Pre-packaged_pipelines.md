This page contains some examples of the pre-packaged pipelines that could be deployed simultaneously with the Cloud Pipeline platform.

General user journey for the usage of any prepared pipeline is the following:

1. Upload the data, that the pipeline will work with, to the input data storage.
2. Prepare a place for the output data in some storage - where results will be loaded once pipeline is completed.
3. Open the **Library** and find the pipeline.
4. Select a pipeline version that should be launched if there are several ones.
5. At the **Launch form**:
    - select a pipeline configuration if needed or leave the default
    - specify values of the pipeline parameters - here, paths to the input data and output results shall be specified, and other parameters if necessary
6. Launch a pipeline run.
7. If necessary, monitor the pipeline execution from the **Run logs** page of the launched pipeline.
8. Once the pipeline run is completed, navigate to the output path - to review pipeline results.

## NextFlow pipelines

[Nextflow](https://www.nextflow.io/index.html) pipelines are workflows constructed from individual, parallel processes that perform computational tasks.  
Processes communicate via channels, which act as queues, enabling a reactive dataflow model.  
This allows for efficient parallelization and scaling, making Nextflow a powerful tool for data-intensive workflows.

> All NextFlow pipelines runs in the Cloud Pipeline platform support special NextFlow visualization - for details see [here](../11_Manage_Runs/11.6._Nextflow_runs_visualization.md).  
> Additionally, via the [GUI plugins](../11_Manage_Runs/11.7._Plugins_framework.md) custom NextFlow view for the **Launch form** can be configured.

### Rnaseq

[**Rnaseq**](https://nf-co.re/rnaseq/) is a bioinformatics pipeline that can be used to analyse RNA sequencing data obtained from organisms with a reference genome and annotation.  
It takes a samplesheet and FASTQ files as input, performs quality control (QC), trimming and (pseudo-)alignment, and produces a gene expression matrix and extensive QC report.

Features that need to be taken into account when preparing and running **Rnaseq** via the Cloud Pipeline platform:

Pipeline overview:  
    ![CP_PreparedPipelineExamples](attachments/PrePackagedPipelines_01.png)

Pipeline parameters:  
    ![CP_PreparedPipelineExamples](attachments/PrePackagedPipelines_02.png)

- **`samplesheet_path`** - input path to the sheet (`CSV`) containing metadata about samples to process
- **`custom_config_path`** - path to the custom Nextflow config for the pipeline including paths to the reference genome `fasta` and reference annotation
- **`output_storage`** - output path where the results will be saved

Example and format of the `samplesheet` file - each row represents a fastq file (single-end) or a pair of fastq files (paired end) for a sample with the strandedness value:

```csv
sample,fastq_1,fastq_2,strandedness
SAMPLE1,<PATH_TO_SAMPLE1_1_FASTQ>,<PATH_TO_SAMPLE1_2_FASTQ>,auto
SAMPLE2,<PATH_TO_SAMPLE2_1_FASTQ>,<PATH_TO_SAMPLE2_2_FASTQ>,auto
SAMPLE3,<PATH_TO_SAMPLE3_1_FASTQ>,<PATH_TO_SAMPLE3_2_FASTQ>,reverse
...
```

Example and format of the `custom_config` file, more details about pipeline steps - you can find in the main **`README.md`** in pipeline documents.

### Sarek

[**Sarek**](https://nf-co.re/sarek/) is a workflow designed to detect variants on whole genome or targeted sequencing data.  
Initially designed for Human, and Mouse, it can work on any species with a reference genome. Sarek can also handle tumour / normal pairs and could include additional relapses.

Features that need to be taken into account when preparing and running **Sarek** via the Cloud Pipeline platform:

Pipeline overview:  
    ![CP_PreparedPipelineExamples](attachments/PrePackagedPipelines_07.png)

Pipeline parameters:  
    ![CP_PreparedPipelineExamples](attachments/PrePackagedPipelines_08.png)

- **`samplesheet_path`** - input path to the sheet (`CSV`) containing metadata about samples to process
- **`custom_config_path`** - path to the custom Nextflow config for the pipeline including paths to the reference genome `fasta` and reference annotation
- **`output_storage`** - output path where the results will be saved  
    **_Note_**: there are several `LFS` parameters - these are Cloud Pipeline platform settings, they are required for the correct pipeline execution and should not be changed by the user

### Proteinfold

[**Proteinfold**](https://nf-co.re/proteinfold/) is a bioinformatics analysis pipeline for Protein 3D structure prediction.  
It leverages deep learning models like `AlphaFold2`, `RoseTTAFold` and `ESMFold` to predict protein structures from amino acid sequences.

Features that need to be taken into account when preparing and running **Proteinfold** via the Cloud Pipeline platform:

### Active Learning Pipeline

**Al-docking** is an active learning-driven molecular docking pipeline that ingests 3D receptor structures and a chemical compound database.  
It iteratively performs docking simulations (`QuickVina`) and trains machine learning models (`DGL`, `PyTorch`) over protein structure files to prioritize promising ligands, producing docking score prediction results, trained models, and a summary report with progress through iteration figures.  

Features that need to be taken into account when preparing and running **Al-docking** via the Cloud Pipeline platform:

Pipeline overview:  
    ![CP_PreparedPipelineExamples](attachments/PrePackagedPipelines_19.png)

Pipeline parameters:  
    ![CP_PreparedPipelineExamples](attachments/PrePackagedPipelines_17.png)

- **`receptor_sheet`** - input path to the sheet (`CSV`) containing metadata about receptor target structures to process
- **`NextFlow -params-file`** - path to the pipeline `JSON`/`YAML` file with workflow parameters to be not overridden by configs
- **`Cache .zip`** - path to the cache `ZIP` file with ligands prepared and docking results
- **`output_storage`** - output path where the results will be saved
- **`custom_config_path`** - path to the custom config containing compound database settings and NextFlow executor settings
- **`NextFlow -dump-channels`** - allows to dump channels output for debugging purpose  

Example and format of the `receptor_sheet` file - each row represents a receptor with its `PDB` path and pocket configuration for ligands' docking:

```csv
id,pdb,pocket_config
RECEPTOR1,<PATH_TO_RCEPTOR1_PDB>,<PATH_TO_RCEPTOR1_POCKET_CONFIG>
RECEPTOR2,<PATH_TO_RCEPTOR2_PDB>,<PATH_TO_RCEPTOR2_POCKET_CONFIG>
...
```

Example of the pocket config file:

```
receptor = <PATH_TO_RCEPTOR1_PDB>

center_x = 14.455
center_y = 75.815
center_z = 36.333

size_x = 66.724
size_y = 108.143
size_z = 111.314
```

### Running Nextflow pipelines on Batch in Google Cloud

This section describes how to extend Cloud Pipeline's main execution backend to run a Nextflow pipeline on Batch in Google Cloud deployment.

> **_Note_**: tutorial runs the sample pipeline from Nextflow based on [RNA-Seq](#rnaseq).

In a nutshell, to enable Batch using for Nextflow pipeline runs, the following conditions shall be met:

- Nextflow pipeline (based on Nextflow docker image) is used for the launch.
- In the `cluster.networks.config` System Preference, configuration section of the machine image, used for the running Nextflow pipelines, contains additional specification that includes GCP service account details. And such service account has corresponding permissions required for running the Batch job.
- `nextflow.config` of the pipeline contains special `google-batch` profile, that is used for the Nextflow pipeline run.

Now, let's take a closer look:

> **_Note_**: before the beginning, make sure that your GCP project has a Virtual Private Cloud (VPC) network with a valid networking configuration.

1. Navigate to the [**System Preferences**](../12_Manage_Settings/12._Manage_Settings.md#preferences) section and find the `cluster.networks.config` preference.
2. In `amis` section, create an item for the machine image that will be used for the running Nextflow pipelines on Batch, e.g. copy the existing general one image item:  
    ![CP_NextflowPipelineOnBatch](attachments/NextflowBatchPipeline_01.png)
3. To the created machine image item, add a Nextflow docker image in the format `"docker_image": "<nextflow_docker_image>`, e.g.:  
    ![CP_NextflowPipelineOnBatch](attachments/NextflowBatchPipeline_02.png)
4. To the created machine image item, add an additional specification that includes GCP service account details in the following format:  

        "additional_spec": {
            "serviceAccounts": [
                {
                    "email": "<gcp_service_account_name>",
                    "scopes": [
                        "https://www.googleapis.com/auth/cloud-platform"
                    ]
                }
            ]
        }

    Where `<gcp_service_account_name>` - name of your [GCP service account](https://cloud.google.com/compute/docs/access/service-accounts). You can find it in the settings of your Google Cloud [region](../12_Manage_Settings/12._Manage_Settings.md#cloud-regions), e.g.:  
    ![CP_NextflowPipelineOnBatch](attachments/NextflowBatchPipeline_06.png)  
    ⚠️ Please note, service account must have the necessary permissions to allow the Batch service agent to create and access resources for Batch jobs. The following IAM roles shall be granted for the service account on the current GCP project:  

    - [Batch Agent Reporter](https://cloud.google.com/iam/docs/roles-permissions/batch#batch.agentReporter) (`roles/batch.agentReporter`)
    - [Storage Admin](https://cloud.google.com/iam/docs/roles-permissions/storage#storage.admin) (`roles/storage.admin`)
    - [Logs Writer](https://cloud.google.com/iam/docs/roles-permissions/logging#logging.logWriter) (`roles/logging.logWriter`)  
    Example of the filled in specification:  
    ![CP_NextflowPipelineOnBatch](attachments/NextflowBatchPipeline_03.png)

5. Save the changes you made in the preference.
6. Open a Nextflow pipeline that you want to launch on Batch in GCP. For our example, we will use [RNA-Seq](#rnaseq).
7. Navigate to the **CODE** tab of the pipeline:  
    ![CP_NextflowPipelineOnBatch](attachments/NextflowBatchPipeline_04.png)
8. Open `nextflow.config` file that defines Nextflow-specific details of the pipeline configuration:  
    ![CP_NextflowPipelineOnBatch](attachments/NextflowBatchPipeline_05.png)
9. To the section `profiles` of the config file, insert a new profile for running on Batch in GCP, e.g. `'google-batch'`. This profile should contain the following:

        'google-batch' {
            params.transcriptome = 'gs://rnaseq-nf/data/ggal/transcript.fa'
            params.reads = 'gs://rnaseq-nf/data/ggal/gut_{1,2}.fq'
            params.multiqc = 'gs://rnaseq-nf/multiqc'
            params.outdir = '<gs_output_path>'
            process.executor = 'google-batch'
            process.container = 'quay.io/nextflow/rnaseq-nf:v1.1'
            workDir = '<gs_workdir_path>'
            google {
                region  = '<gcp_region>'
                project = '<project_id>'
                location = '<gcp_region>'
                batch {
	                serviceAccountEmail = '<gcp_service_account_name>'
                    network = 'global/networks/<gcp_network>'
                    subnetwork = 'regions/<gcp_region>/subnetworks/<gcp_subnetwork>'
                    allowedLocations = ['regions/<gcp_region>']
                }		
            }
        }

    Where shall be specified:  

    - `<gs_output_path>` - path inside your Google Cloud storage where results will be output
    - `<gs_workdir_path>` - path inside your Google Cloud storage where logs and intermediate results will be stored
    - `<gcp_region>` - name of the GCP region that is used.
    - `<project_id>` - your GCP project ID. You can find it in the settings of your Google Cloud [region](../12_Manage_Settings/12._Manage_Settings.md#cloud-regions), e.g.:  
    ![CP_NextflowPipelineOnBatch](attachments/NextflowBatchPipeline_07.png)
    - `<gcp_service_account_name>` - name of your [GCP service account](https://cloud.google.com/compute/docs/access/service-accounts). You can find it in the settings of your Google Cloud [region](../12_Manage_Settings/12._Manage_Settings.md#cloud-regions), e.g.:  
    ![CP_NextflowPipelineOnBatch](attachments/NextflowBatchPipeline_06.png)
    - `<gcp_network>` - name of your job's network
    - `<gcp_subnetwork>` - name of your job's subnetwork  
    You can find values for network and subnetwork in the `cluster.networks.config` [preference](../12_Manage_Settings/12._Manage_Settings.md#preferences), in section of the GCP region definition, e.g.:  
    ![CP_NextflowPipelineOnBatch](attachments/NextflowBatchPipeline_08.png)  
    Example of the filled in profile:  
    ![CP_NextflowPipelineOnBatch](attachments/NextflowBatchPipeline_09.png)

10. Save changed `nextflow.config` file.
11. Specify the use of the just-created profile for the main `nextflow run` command of your pipeline using the `-profile` option, e.g.:  
    ![CP_NextflowPipelineOnBatch](attachments/NextflowBatchPipeline_10.png)

    > Another place, where this command may be specified - main script at the **CODE** tab of the pipeline page, e.g.:  
    >   ![CP_NextflowPipelineOnBatch](attachments/NextflowBatchPipeline_11.png)

    Save changes.

12. Now, you may launch your Nextflow pipeline as [usual](6.2._Launch_a_pipeline.md).
13. During the pipeline running, you may follow the Nextflow Batch execution logs in the console, e.g.:  
    ![CP_NextflowPipelineOnBatch](attachments/NextflowBatchPipeline_12.png)
14. After the pipeline finishes running, it stores result files by the output path inside Google Cloud storage that was specified in the `'google-batch'` profile of the pipeline's `nextflow.config` file previously.  
    You may view them using **Library** GUI, e.g.:  
    ![CP_NextflowPipelineOnBatch](attachments/NextflowBatchPipeline_13.png)
