# Extract archive from the storage's selection menu

Test verifies that an archive already in a storage is extracted from the selection menu, with no
pop-up in between: the **Extract archive** item sits below **Download archive**, is offered for a
single selected archive as well as several, and queues one task per selected archive straight away.

**_Note_**: the service that carries out an extraction is not part of this version. A queued task is
listed in the **Storage tasks** window and stays in its pending state, so this case checks that the
tasks are queued and listed - not that any extracted file appears in the storage. Once that service
exists, each archive is extracted into a new folder beside it named after the archive without its
extension, and the archive itself is kept.

**Prerequisites**:
- A user with **READ** and **WRITE** permissions on an S3 object storage (or an NFS storage whose
  share is mounted as NFS)

**Preparations**:
1. Login as the user from the Prerequisites
2. Open the storage from the Prerequisites
3. Upload two archive files (e.g. `one.zip`, `two.tar.gz`) and one ordinary file (e.g. `notes.txt`)
   into the storage, choosing **Upload** - not **Upload and extract** - so that nothing is queued
4. Create a folder in the storage whose name ends in `.zip` (e.g. `folder.zip`)

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Select `one.zip` alone using its checkbox, then click the selection button (shown as **"1 item selected"**) | <li> An **Extract archive** item is listed, directly below **Download archive** <li> It is offered even though only one item is selected, unlike **Download archive** |
| 2 | Click **Extract archive** | <li> No pop-up opens - the task is queued straight away <li> A loading message reading `Starting archive extraction...` appears briefly <li> It is replaced by a message reading `Archive extraction has been queued. Follow its progress under "Show storage tasks".`, with **Show storage tasks** as a clickable link |
| 3 | Click the **Show storage tasks** link inside that message | <li> The message closes and the **Storage tasks** window opens <li> One new row is listed, with **Extract archive** in its **Type** column and `one.zip` as its name <li> Its **Actions** offer **Cancel** and no **Download** |
| 4 | Close the window, select `one.zip` and `two.tar.gz` together, and choose **Extract archive** | A message reads `Extraction of 2 archives has been queued. Follow their progress under "Show storage tasks".` - the plural wording, and one task per archive |
| 5 | Open the **Storage tasks** window | Three **Extract archive** tasks are listed in all - the one from step 2 and the two from step 4 - each naming its own archive |
| 6 | Close the window, select `notes.txt` alone, and click the selection button | No **Extract archive** item is listed: the file is not an archive |
| 7 | Select the `folder.zip` folder alone and click the selection button | No **Extract archive** item is listed: a folder is never an archive, whatever it is called |
| 8 | Select `notes.txt` and `one.zip` together and choose **Extract archive** | <li> A message reads `Archive extraction has been queued...` - singular <li> The **Storage tasks** window lists one new task, for `one.zip` alone: the ordinary file in the selection is ignored |

**After**:
- Cancel every **Extract archive** task in the **Storage tasks** window
- Delete `one.zip`, `two.tar.gz`, `notes.txt` and the `folder.zip` folder from the storage
