# "Capacity retries" applies to every "Fallback node types" entry too

Test verifies that when ***Fallback node types*** are specified together with ***Capacity retries***, the autoscaler retries the primary node type and then each fallback node type, in order, on every cycle - so once the run fails, the ***InitializeNode*** task log contains exactly the ***Capacity retries*** number of `Insufficient instance capacity.` records for the primary type, and the same number for each fallback type.

**Prerequisites**:
- Admin user
- Test tool available in the registry
- Node types `type1` and `type2` of rare compute instance types for the current Cloud Provider, launch attempts for both of which can lead to the exception of insufficient capacity of such node types for the Cloud Region
- Perform [4608_2](4608_2.md) case

**Preparations**:
1. Login as the admin user from the prerequisites
2. Open the **Settings** page
3. Click the **PREFERENCES** tab, then the **Launch** tab
4. Save the `launch.run.reschedule.enabled` preference value, then uncheck *Enabled* checkbox for `launch.run.reschedule.enabled` preference if needed. Click **Save** button if needed
5. Open the **Tools** page, select the test tool from the prerequisites
6. Click the **SETTINGS** tab
7. Expand the **EXECUTION ENVIRONMENT** section
8. Save the ***Allow reschedule to different region in case of insufficient capacity*** value, then select ***Not Configured*** option if needed. Click **SAVE** button if needed
