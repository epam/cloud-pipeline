# The archive-task allowance governs Upload and extract, and frees up on its own

Test verifies that:
- one archive is one task, so a batch needing more archive tasks than the user has allowance left
 makes **Upload and extract** unavailable, with the reason shown in the pop-up
- **Upload** and **Cancel** keep working while it is unavailable
- the allowance is shared with archive downloads rather than counted separately
- the pop-up keeps checking while it is open, so freeing a slot makes the button available again
 without closing the pop-up and picking the files afresh

**Prerequisites**:
- An admin user
- A non-admin user with **READ** and **WRITE** permissions on an S3 object storage (or an NFS storage whose
 share is mounted as NFS)

**Preparations**:
1. As the administrator, set `maxUserTasks` in the `system.async.tasks.config` preference to `2`
2. Login as the user from the Prerequisites
3. Open the storage from the Prerequisites
4. On the local machine, have ready three archive files (e.g. `a1.zip`, `a2.zip`, `a3.zip`)
5. Select a folder in the storage, choose **Download archive** from the selection button, and
 confirm with **OK** - so one of the two allowed tasks is an archive *download*, not an extraction

| Steps | Actions | Expected results |
|:---:|---|---|
| 1 | Click the **Upload** button, select `a1.zip`, `a2.zip` and `a3.zip` together and confirm | <li> The **Upload files** pop-up opens, listing the three files <li> **Upload and extract** is disabled <li> An informational message `3 archives are selected, and you may start only 2 more archive tasks right now. Wait for one of your archive tasks to finish, or cancel one.` is shown inside the pop-up <li> **Upload** and **Cancel** are both clickable |
| 2 | Click **Upload** in that pop-up | All three files are uploaded as an ordinary upload, with no extraction queued and no message about extraction |
| 3 | Delete `a1.zip`, `a2.zip` and `a3.zip` from the storage. Click **Upload**, select `a1.zip` alone and confirm | <li> The **Upload files** pop-up opens <li> **Upload and extract** is available <li> No informational message is shown |
| 4 | Click **Upload and extract** | |
| 5 | Select several files, click the **N items selected** button, click **Download archive**, then click **OK** | |
| 6 | Click **Upload**, select `a1.zip` alone and confirm | <li> **Upload and extract** is greyed out <li> The pop-up's message `You already have 2 archive tasks in progress, and the limit is 2. Wait for one to finish before starting another.` is shown. |
| 7 | Leaving that pop-up open, wait until one of the two tasks in the **Storage tasks** window is finished , and wait a few seconds without touching the pop-up | <li> **Upload and extract** becomes available on its own <li> The informational message disappears |
| 8 | Click **Upload and extract** and wait for the upload to finish | A message reads `Archive extraction has been queued. Follow its progress under "Show storage tasks".` - singular, with no second message, since there is now allowance for it |

**After**:
- Delete `a1.zip` from the storage
- As the administrator, put `maxUserTasks` back to its original value
