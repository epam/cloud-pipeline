# The Storage tasks window: its columns, the task type, and filtering on one type

Test verifies that:
- the **Storage tasks** window lists every kind of archive task, not archive downloads alone
- the **Type** column names each one in words - **Download archive** or **Extract archive** - rather
  than showing the raw value the API returns
- the **Type** column's own filter offers **Any type** plus one option per type, and takes **one** of
  them at a time, unlike the **Status** column's checkbox list
- **OK** applies the chosen type, and only tasks of that type remain listed
- **Reset to defaults** in that filter, and the window's own **Reset filters** control, both bring
  back every type
- the table's columns are **Type**, the archive name, **Source**, **Size**, **Status** and
  **Actions** - with no **Created** or **Finished** - and the **Source** cell links to the folder
  the task was queued from, shortened to fit the column with the whole path on hover

**Prerequisites**:
- A user with **READ** and **WRITE** permissions on an S3 object storage (or an NFS storage whose
  share is mounted as NFS)

**Preparations**:
1. Login as the user from the Prerequisites
2. Open the storage from the Prerequisites
3. On the local machine, have ready one archive file (e.g. `archive1.zip`)
4. Upload `archive1.zip` via **Upload** → **Upload and extract**, so that one extraction task is
   queued (see case 4571_4)
5. Select a folder in the storage, click the selection button and choose **Download archive**,
   confirm the name with **OK**, so that one archive-download task is queued
6. Open the presentation dropdown (the button with the grid icon at the top right of the storage
   view) and choose **Show storage tasks**

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Look at the table | <li> Both tasks from Preparations are listed <li> A **Type** column is shown, before the archive name <li> The extraction task reads **Extract archive** and the download task reads **Download archive** - neither cell shows an upper-case value with underscores |
| 2 | Look at the table's columns | <li> They are **Type**, the archive name, **Source**, **Size**, **Status** and **Actions** - plus **Owner** for an administrator <li> There is no **Created** and no **Finished** column |
| 3 | Look at the **Source** cell of each task, and hover it | <li> It reads `<storage name>/<folder>` - for the extraction, the folder the archive sits in; for the download, the folder the selection was made in <li> A path too long for the column is shortened with an ellipsis, and hovering the cell shows the whole of it |
| 4 | Click the **Source** cell of the extraction task | <li> The **Storage tasks** window closes <li> The storage browser opens that storage at that folder |
| 5 | Click the filter icon in the **Type** column's header | A filter opens, offering **Any type**, **Download archive** and **Extract archive**, with **OK** and **Reset to defaults** underneath |
| 6 | Select **Extract archive** | <li> **Extract archive** becomes the selected option <li> **Any type** and **Download archive** are deselected - selecting one option clears the other, rather than adding to it |
| 7 | Click **OK** | <li> The filter closes <li> Only the extraction task is listed; the archive-download task is gone <li> The **Type** column's filter icon is highlighted as active <li> A **Reset filters** control appears above the table |
| 8 | Open the **Type** filter again and select **Download archive**, then click **OK** | Only the archive-download task is listed; the extraction task is gone |
| 9 | Open the **Type** filter again and click **Reset to defaults** | <li> The filter closes <li> Both tasks are listed again <li> The **Type** column's filter icon is no longer highlighted |
| 10 | Open the **Type** filter, select **Extract archive**, click **OK**, then click **Reset filters** above the table | <li> Both tasks are listed again <li> The **Reset filters** control disappears - there is nothing left to reset |

**After**:
- Cancel the extraction task in the **Storage tasks** window
- Cancel the archive-download task, or wait for it to finish
- Delete `archive1.zip` from the storage
