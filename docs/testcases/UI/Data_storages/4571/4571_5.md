# The Storage tasks window: its columns, the task type, and filtering on one type

Test verifies that:
- the **Storage tasks** window lists every kind of archive task
- the table's columns are **Type**, **Archive**, **Source** (links to the folder), **Size**, **Status**, **Owner** and **Actions**
- the **Type** column names each one in words - **Download archive** or **Extract archive**
- the table can be filtered by **Type** column
- **Reset to defaults** in that filter, and the window's own **Reset filters** control, both bring back every type

**Prerequisites**:
- A non-admin user with **READ** and **WRITE** permissions on an S3 object storage (or an NFS storage whose
 share is mounted as NFS)

**Preparations**:
1. Login as the user from the Prerequisites
2. Open the storage from the Prerequisites
3. On the local machine, have ready one archive file (e.g. `archive1.zip`)
4. Upload and extract `archive1.zip` via **Upload** → **Upload and extract**
5. Select a folder in the storage, click the selection button and choose **Download archive**, confirm the name with **OK**
6. Create a nested folder whose path is long enough to be shortened in the **Source** column (e.g.
 `storage-tasks-source-column-check/one-more-level-below-it/`), open it, and upload and extract a
 copy of `archive1.zip` there via **Upload** → **Upload and extract**

| Steps | Actions | Expected results |
|:---:|---|---|
| 1 | Click the grid icon at the top right of the storage view and choose **Show storage tasks** | **Storage tasks** window opens that contains <li> **Type**, **Archive**, **Source**, **Size**, **Status**, **Owner** and **Actions** columns <li> Both tasks from Preparations are listed <li> The extraction task reads **Extract archive** and the download task reads **Download archive** |
| 2 | For each task hover over the link in the **Source** cell | <li> It reads `<storage name>/<folder>` - for the extraction, the folder the archive sits in; for the download, the folder the selection was made in <li> A path too long for the column is shortened with an ellipsis, and hovering the cell shows the whole of it <li> The long path from Preparations wraps onto further lines inside the hint's own box, rather than running past its edge |
| 3 | Click the **Source** cell of the extraction task | <li> The **Storage tasks** window closes <li> The storage browser opens that storage at that folder |
| 4 | Click the grid icon at the top right of the storage view and choose Show storage tasks | |
| 5 | Click the filter icon in the **Type** column's header | A filter opens, offering **Any type**, **Download archive** and **Extract archive**, with **OK** and **Reset to defaults** underneath |
| 6 | Select **Extract archive**. Click **OK** | <li> The filter closes <li> Only the extraction tasks are listed; the archive-download tasks are gone <li> The **Type** column's filter icon is highlighted as active <li> A **Reset filters** control appears above the table |
| 7 | Open the **Type** filter again and select **Download archive**, then click **OK** | Only the archive-download tasks are listed |
| 8 | Open the **Type** filter again and click **Reset to defaults** | <li> The filter closes <li> Both tasks are listed again <li> The **Type** column's filter icon is no longer highlighted |
| 9 | Open the **Type** filter, select **Extract archive**, click **OK**, then click **Reset filters** above the table | <li> Both tasks are listed again <li> The **Reset filters** control disappears - there is nothing left to reset |
| 10 | Make the browser window narrow enough to squeeze the table's columns, and look at the **Status** and **Owner** cells | Each of them stays on one line: neither a status nor an owner name is broken across two lines, so the rows keep an even height |

**After**:
- Delete `archive1.zip`, the folder created in Preparations, and the folders the extractions wrote,  from the storage
