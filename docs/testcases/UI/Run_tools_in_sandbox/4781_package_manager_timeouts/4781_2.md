# A stalled yum call of the Cloud Pipeline repo setup is reported in the run log and tried again

Test verifies that:
- a `yum` install of the Cloud Pipeline repo setup that hangs is stopped after `CP_PKG_MANAGER_INSTALL_TIMEOUT_SEC` seconds
- the run log shows that `yum` was stopped, although the `yum` output goes to `/var/log/yum.cp.log`
- the next attempt of the repo setup sets up the Cloud Pipeline yum repo, and the run starts

**Prerequisites**:
- Admin user
- Test tool based on Rocky Linux 8.7, available in the registry. The Cloud Pipeline yum repo exists for its version: a run of the tool with the default settings logs no `Failed to configure` row in its *Console* task
- The tool image's `PATH` has `/usr/local/sbin` before `/usr/bin`, as Docker's default `PATH` does. The command `tr '\0' '\n' < /proc/1/environ | grep '^PATH='` in an SSH session of a run of the tool shows the image's `PATH`
- The `launch.pre.common.commands` preference has no other command for Rocky Linux that runs `yum`: such a command would run into the hang before the Cloud Pipeline repo setup

**Preparations**:
1. Login as the admin user from the prerequisites
2. Open the **Settings** page
3. Click the **PREFERENCES** tab
4. Click the **Launch** tab
5. Find the `launch.pre.common.commands` preference
6. Save the preference value. Add the `test_yum_hang_once` entry below into the `pre_init` → `linux` → `rocky` → `default` object of the value if the value has a `pre_init` section, otherwise into its `linux` → `rocky` → `default` object, creating the missing levels. If the value is empty, input the JSON as it is:
   ```json
   {
     "linux": {
       "rocky": {
         "default": {
           "test_yum_hang_once": [
             "[ -z \"$TEST_YUM_HANG_ONCE\" ] || { mkdir -p /usr/local/sbin && printf \"#!/bin/bash\\n[ -f /tmp/test-yum-hung ] || { touch /tmp/test-yum-hung; sleep 1800; }\\nexec /usr/bin/yum \\\"\\$@\\\"\\n\" > /usr/local/sbin/yum && chmod +x /usr/local/sbin/yum && hash -r; }"
           ]
         }
       }
     }
   }
   ```
   The command does nothing in a run without the `TEST_YUM_HANG_ONCE` parameter. In a run with it, the first `yum` call hangs for 30 minutes
7. Click **Save** button
