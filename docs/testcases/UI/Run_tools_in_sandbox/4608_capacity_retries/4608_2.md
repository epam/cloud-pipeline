# "Capacity retries" field appears on the Tool launch form when `ui.launch.allow.nodeup.count` is on

Test verifies that enabling the `ui.launch.allow.nodeup.count` system preference shows an optional ***Capacity retries*** field on the Tool launch form, empty by default with the `cluster.nodeup.retry.count` preference value shown as a placeholder, and a hint describing it.

**Prerequisites**:
- Admin user
- Test tool available in the registry

**Preparations**:
1. Login as the admin user from the prerequisites
2. Open the **Settings** page
3. Click the **PREFERENCES** tab
4. Click the **Cluster** tab
5. Find the `cluster.nodeup.retry.count` preference value (`N`)
6. Click the **User Interface** tab
7. Find the `ui.launch.allow.nodeup.count` preference
8. Save the preference value, then check *Enabled* checkbox for `ui.launch.allow.nodeup.count` preference if needed
9. Click **Save** button if needed

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Open the **Tools** page | |
| 2 | Select the test tool from the prerequisites | |
| 3 | At the tool page, hover over the **Run v** button | |
| 4 | Click the **Custom settings** button in the list | |
| 5 | Expand the **Exec environment** section | ***Capacity retries*** field is shown, empty, with placeholder `N`, where `N` is the `cluster.nodeup.retry.count` value from the preparations |
| 6 | Hover over the hint icon near the ***Capacity retries*** label | Tooltip appears with the text: <br>`The number of attempts to start a compute node before the run fails or is rescheduled to another region. Optional: when it is empty, the run uses the cluster.nodeup.retry.count system preference, shown as the placeholder. The maximum is 999, or that preference's value if it is higher.` |

**After**:
- Preference `ui.launch.allow.nodeup.count` stays enabled: it is required by [4608_3](4608_3.md) - [4608_7](4608_7.md) cases, and is restored to its original value at the end of [4608_7](4608_7.md)
