# ROLE_PIPELINE_READER and ROLE_PIPELINE_EXECUTOR: read and launch access to existing pipelines

Test verifies that:
- a user with role PIPELINE_READER has a read access to all pipelines registered in the system and to all their runs, even if the pipeline permissions deny it and the run visibility policy is `OWNER`
- a user with role PIPELINE_READER is not able to launch a pipeline, unless a permission to do so is granted explicitly
- a user with both roles PIPELINE_READER and PIPELINE_EXECUTOR is able to launch all pipelines, but is not able to manage the runs of other users

**Prerequisites**:
- Admin user
- Non-admin user

**Preparations**
1. Login as admin user from the prerequisites
2. Create the pipeline `pipeline1` from any template. Make sure the non-admin user from the prerequisites has **Execute** permission to the Docker image of the pipeline.
3. Open the permissions of `pipeline1`, add the non-admin user from the prerequisites and deny **Read** and **Execute** to that user.
4. Launch `pipeline1` and wait until the run gets the `Running` status.
5. Open the **Settings** page >> **PREFERENCES** tab >> **Launch** section. Set the `launch.run.visibility` preference to `OWNER`. Save changes.

**After**:
- Set the `launch.run.visibility` preference to its previous value
- Stop the runs launched by the test
- Remove the roles `ROLE_PIPELINE_READER` and `ROLE_PIPELINE_EXECUTOR` from the non-admin user from the prerequisites
