# A run on a shareable pool gets the CPU/RAM/GPU requests set on the launch form

Test verifies that:
- a shareable pool from the **Pools** group shows the CPU/RAM/GPU request fields
- the run gets `CP_CAP_POOL_ID` and the `CP_CAP_REQUESTS_*` parameters with the values that were set
- the request fields disappear when a plain instance type is selected

**Prerequisites**:
- Admin user
- Test tool available in the registry
- Pools from the Preparations of [4960_1](4960_1.md) case

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Open the **Cluster state** page, the **HOT NODE POOLS** tab | |
| 2 | Click `pool-shareable-default` and save the `pool_id` value from the page URL | |
| 3 | Open the **Tools** page | |
| 4 | Select the test tool from the prerequisites | |
| 5 | At the tool page, hover over the **Run v** button | |
| 6 | Click the **Custom settings** button in the list | |
| 7 | Expand the **Exec environment** section | |
| 8 | In the ***Node type*** field, select the `pool-shareable-default` entry of the **Pools** group | The ***CPU request*** and ***RAM request*** fields are shown |
| 9 | Set `2` in the ***CPU request*** field and `4` in the ***RAM request*** field | |
| 10 | Click the **Launch** button | |
| 11 | In an appeared pop-up window click **Launch** button | |
| 12 | At the **Runs** page, click the just-launched run | |
| 13 | Expand the **Parameters** section | <li> `CP_CAP_POOL_ID` is shown, with the pool ID saved at step 2 <li> `CP_CAP_REQUESTS_CPU` is `2` <li> `CP_CAP_REQUESTS_RAM` is `4` |
| 14 | Repeat steps 3-7 | |
| 15 | In the ***Node type*** field, select the `pool-shareable-default` entry of the **Pools** group | The ***CPU request*** and ***RAM request*** fields are shown |
| 16 | In the ***Node type*** field, select the instance type of `pool-shareable-default` from its family group (with no tag) | The ***CPU request*** and ***RAM request*** fields are not shown |
| 17 | Repeat steps 10-12 | |
| 18 | Expand the **Parameters** section | `CP_CAP_POOL_ID` and the `CP_CAP_REQUESTS_*` parameters are not shown |

**After**:
- stop the runs launched at steps 11 and 17
