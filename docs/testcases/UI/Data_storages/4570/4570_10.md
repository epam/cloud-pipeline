# Downloads window: the Owner filter takes a user picked from its suggestion list

Test verifies that:
- typing into the **Owner** column's filter field offers a list of matching users, and picking one applies that user's name
- the table then shows only that user's tasks, and the **Owner** column's filter icon is highlighted
- a name that was only typed, with nothing picked from the list, is **not** applied: the table keeps showing what the previous selection matched
- while the field holds such a name, the dropdown explains that a user has to be picked from the list, or the field emptied
- leaving the field drops such a name - it goes back to the name it held before the typing, and the explanation disappears with it
- closing the dropdown with such a name in the field applies nothing either

**Prerequisites**:
- Admin user (or a user with the **ROLE_STORAGE_ADMIN** role)
- Non-admin user, without the **ROLE_STORAGE_ADMIN** role
- An S3 object storage (or an NFS storage whose share is mounted as NFS) both users can access, holding at least two files

**Preparations**:
1. Login as the non-admin user from the Prerequisites
2. Open the storage from the Prerequisites, select a file via its checkbox, click the selection button, choose **Download archive**, then click **OK** without changing the offered name
3. Logout, then login as the admin user from the Prerequisites
4. Open the same storage, select the other file, and queue an archive the same way
5. Open the **Downloads** window: click the grid-icon button at the top right of the storage view and choose **Show downloads**

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Click the filter icon on the **Owner** column's header | <li> The filter dropdown opens with an input field holding the admin user's own user name <li> Below it there are two links, **OK** and **Reset to defaults** |
| 2 | Delete the user name from the field, then type the first few characters of the non-admin user's name | <li> A list of matching users appears under the field <li> A line under the field says that a user has to be picked from the list, or the field emptied to show every user's tasks |
| 3 | Click **OK** without picking anyone from the list | <li> The dropdown stays open <li> The table does not reload, and still shows only the admin user's own task <li> The typed name is dropped from the field, which goes back to the state it was in before the typing - empty, since it was emptied at step 2 - and the line from step 2 disappears with it <li> **OK** is live again, and pressing it now would apply the empty field, i.e. every user's tasks - do not press it |
| 4 | Type the first few characters of the non-admin user's name again, pick that user from the list, then click **OK** | <li> The line from step 2 appears again while the name is only typed, and disappears as soon as the user is picked <li> The dropdown closes and the table reloads <li> Only the non-admin user's task, queued at step 2 of Preparations, is shown, with that user's name in the **Owner** column <li> The **Owner** column's filter icon is highlighted <li> A **Reset filters** button appears above the table |
| 5 | Click the filter icon on the **Owner** column's header again, delete the name from the field, type a user name that does not exist, then click somewhere outside the dropdown | <li> No matching user is offered, and the line from step 2 is shown while the name is in the field <li> The dropdown closes <li> The table does not reload, and still shows only the non-admin user's task - nothing was applied |
| 6 | Click the filter icon on the **Owner** column's header, then click **Reset to defaults** | <li> The dropdown closes and the table reloads <li> Only the admin user's own task is shown again <li> The **Owner** column's filter icon is no longer highlighted, and the **Reset filters** button disappears |

**After**:
- Cancel both tasks queued in Preparations from the **Downloads** window of the user who owns each, or let them finish and discard the downloaded archives
