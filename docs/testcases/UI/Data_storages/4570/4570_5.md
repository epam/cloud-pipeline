# Downloads window: the Owner column is admin/ROLE_STORAGE_ADMIN-only

Test verifies that:
- a regular user's **Downloads** window has no **Owner** column and no owner filter, and only ever shows their own tasks
- an administrator, or a user with the **ROLE_STORAGE_ADMIN** role, sees an **Owner** column with its own filter, and by default the table still shows only their own tasks

**Prerequisites**:
- Admin user
- Non-admin user, without the **ROLE_STORAGE_ADMIN** role
- An AWS S3 object storage both users can access, with at least 2 files, exists

| Steps | Actions | Expected results |
| :---: | --- | --- |
| 1 | Login as the non-admin user from the prerequisites |  |
| 2 | Open the storage from the prerequisites |  |
| 3 | Select the 2 files, click the **2 items selected** button, click **Download archive**, then click **OK** |  |
| 4 | Open the **Downloads** window via the grid-icon button's **Show downloads** item | The table has no **Owner** column |
| 5 | Logout, then login as the admin user from the prerequisites |  |
| 6 | Open the storage from the prerequisites |  |
| 7 | Repeat steps 3-4 | <li> The table has an **Owner** column, with a filter icon on its own header <li> By default the table shows only the admin user's own tasks, not the task queued at step 3 by the non-admin user |
| 8 | Click the filter icon on the **Owner** column's header and clear the filter | The task queued at step 3 by the non-admin user is now shown, with that user's name in the **Owner** column |
