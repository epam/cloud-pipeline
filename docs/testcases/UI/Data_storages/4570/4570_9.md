# [MANUAL] A finished archive expires once the `ttlDays` configured in `system.async.tasks.config` has passed

Test verifies that:
- a task whose archive finished (`SUCCESS`) moves to `EXPIRED` once more than `ttlDays` has passed
  since it finished - within a few minutes of that deadline, not only on the exact moment
- an `EXPIRED` task's **Actions** column offers no **Download** button, same as a task that never
  succeeded
- the archive object itself is removed from the destination storage once the task expires

**Prerequisites**:
- Admin user, with **READ** access to the data storage that `system.async.tasks.config`'s
  `tasks.storageDownloadAsArchive.destinationStorageId` field names as the archive destination
- A user with **READ** and **WRITE** permissions on an S3 object storage (or an NFS storage whose
  share is mounted as NFS)

**Preparations**:
1. Login as the admin user from the Prerequisites
2. Open the **Settings** page. Click the **PREFERENCES** tab, then the **Data storage** tab
3. Find the **`system.async.tasks.config`** preference and save its current value
4. Set its `tasks.storageDownloadAsArchive.ttlDays` field to `1`. Click **Save**
5. Note the storage `tasks.storageDownloadAsArchive.destinationStorageId` names, and the
   `destinationPrefix` folder inside it
6. Login as the user from the Prerequisites, open the storage from the Prerequisites, select a
   several files via there checkboxes, click the selection button and choose **Download archive**, then click
   **OK** without changing the offered name
7. Open the **Downloads** window (the grid-icon button at the top right of the storage view, then
   **Show downloads**) and wait until the task's status becomes `SUCCESS`. Note the archive's name
   and finished date/time shown on its row
8. Open the destination storage noted at step 5 and confirm the archive object is there, under the
   `destinationPrefix` folder

| Steps | Actions | Expected results |
| :---: |---| --- |
| 1 | Wait until at least 1 day and a few minutes have passed since the **Finished** time noted at step 7 of Preparations | |
| 2 | Open the **Downloads** window again | The task's status is now `EXPIRED` |
| 3 | Look at the **Actions** column of that row | No **Download** button is offered |
| 4 | Open the destination storage noted at step 5 of Preparations, under the `destinationPrefix` folder | The archive object seen at step 8 of Preparations is gone |

**After**:
- Restore the `system.async.tasks.config` preference to the value saved at step 3 of Preparations
