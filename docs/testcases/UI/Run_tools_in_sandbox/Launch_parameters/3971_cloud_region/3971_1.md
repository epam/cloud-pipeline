# Mount rules: Mount None Storages located in cloud region

Test verifies that storages aren't mounted to the instances independently of instance regions if option `None` is selected for *Object storages* and *File storages* in the Cloud region *Mount rules*.

**Prerequisites**:
- admin user

**Preparations**
1. Login as admin user from the prerequisites
2. Create object storage `storage1` in Cloud region `region1` with `/testdir` *Mount point*.
3. Create object storage `storage2` in Cloud region `region2` with `/testdir` *Mount point*.
4. Create FS data storage `nfs_storage1` in Cloud region `region1` with `/testdir` *Mount point*.

| Steps | Actions | Expected results |
| :---: |--- | --- |
| 1 | Open the **Settings** page | |
| 2 | Click the **CLOUD REGIONS** tab | |
| 3 | Select `region1` on the left panel | |
| 4 | In the **Mount rules:** section select <li> option `None` for ***Object storages*** <li> option `None` for ***File storages***. | |
| 5 | Click **Save** button | |
| 6 | Open the **Tools** page. Select the test tool | |
| 7 | At the tool page, hover over the **Run v** button | |
| 8 | Select the ***Custom settings*** option in the list | |
| 9 | Expand ***Exec environment*** section | |
| 10 | Select `region1` for **Cloud Region** | |
| 11 | Expand ***Advanced*** section | |
| 12 | Click on the text field in the **Limit mounts** section | |
| 13 | In an appeared ***Select data storages to limit mounts*** pop-up click the **Clear selection** button. | |
| 14 | Input `storage1` name into the *Search* field | `storage1`is missing in the available storages list |
| 15 | Input `nfs_storage1` name into the *Search* field | `nfs_storage1` is missing in the available storages list |
| 16 | Navigate to ***Exec environment*** section. Select `region2` for **Cloud Region** | |
| 17 | Repeat steps 12-15 | The same result |
